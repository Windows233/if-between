# IF 机制

《IF：如果之间》的核心机制。

玩家在剧情的关键节点上看见某个角色脑子里的**一条规则** ——
`if "…" then "…"`，然后把下面的选项块拖进去改掉它。改对了，剧情走向就变。

**这份文档是 IF 机制的唯一起点。** 散落的实现细节都能在代码里翻到，
但"它到底是什么、为什么这么做、哪些地方不许动"集中在这儿。

代码位置：

| 管什么 | 在哪 |
|---|---|
| 界面（画框、拖块、确定按钮） | `ui/if_panel.gd` |
| 演出指令（剧本怎么写、怎么等玩家） | `scenes/cutscene.gd` 的 `_if_panel()` |
| 按结果分岔 | `core/story_node.gd` 的 `next_when` |
| 数据自查 | `tools/check_data.py` 的 `NODE_KEYS` / `check_node_keys` |

---

## 一、玩家看到什么

```
┌────────────────────────────────────────┐
│      if "发现异常"   then "观察"          │  ← 两格，各放一个块
│   ────────────────────────────────     │  ← 分隔线
│   [空]  [立即离开]  [空]  [空]     [确定]  │  ← 四个候选格 + 确定
└────────────────────────────────────────┘
```

- **`if` 那格和 `then` 那格都是「块位」**，各放一个选项块
- 下面四个格子是**候选**（按 A/B/C/D 数）
- **拖动规则：把某一块拖到某个块位上，两块换位置。**
  被顶掉的那块自动回到你拖出来那一格 —— 这一条是策划定的，别改
- 按「确定」结算

**格子的空和有，是设计的一部分**：`then` 里那个"观察"本来就是 A 格的内容，
摆上去之后 A 格就空了。所以第一版的画面就是「A 空格、C 空格」——
策划说的「选项 A 一开始就是空着的」「发现异常原本位置为选项 C」都是这个意思。

## 二、一次交互的完整流程

```
玩家走到 A 旁边按交互
      ↓
剧本节点演到 if_panel 指令
      ↓
IfPanel.open(condition, then_block, if_block)     ← 摆两个块位
  + set_slot_block(i, …) × 4                      ← 摆四个候选格
  + set_read_only(disabled)                       ← 纯展示的话锁上
  + remember_layout()                             ← 记下开局那套（复位要用）
      ↓
玩家拖块（_begin_drag → _end_drag → _swap_slots）
      ↓
玩家按「确定」（IfPanel.confirmed 信号）
      ↓
IfPanel.judge(solve) → SOLVED / UNTOUCHED / WRONG
      ↓
  SOLVED     → 写 flag=true，往下演
  UNTOUCHED  → 写 flag=false，往下演（或配了 wrong 就直接跳）
  WRONG      → IfPanel.reset_blocks()，让玩家重排
      ↓
下游节点用 next_when 读那个 flag 决定去哪
```

## 三、数据怎么写

```json
{
  "do": "if_panel",
  "condition": "猫不见了",
  "if_block": "猫不见了",
  "then": "来找主角帮忙",
  "blocks": ["", "立即离开", "", ""],
  "solve": "立即离开",
  "flag": "gate/saved_a",
  "disabled": false,
  "hold": 0
}
```

| 字段 | 什么意思 |
|---|---|
| `if_block` / `then` | 两个块位里**先放着**哪一块 |
| `condition` | **老兜底**：`if` 后面没摆块的时候显示这串固定文字。新数据请用 `if_block` |
| `blocks` | 下面四格（空串 = 空位） |
| `solve` | 拖到 `then` 的**得是这块**才算过。不写就是纯展示 |
| `flag` | 「改没改对」写进哪个状态位。下游节点用 `next_when` 读它 |
| `wrong` | **老写法**：什么都没改时直接跳这个节点。现在更推荐用 `flag` + `next_when`（见第四节） |
| `disabled` | 纯展示（拖不动，两个块位里的块也拽不走） |
| `hold` | 停这么久自己收；不写就等玩家按确定 |

### 三条硬规矩

1. **`if` 位不许动。** 判定里第一条就是「`if` 位必须还是开局那个值」——
   只判 `then` 的话，把答案拖到 `if` 上、`then` 没动就蒙混过去了。
2. **合规组合要一次说清。** 现在只有两种：
   `if 发现异常 then 观察`（没改）和 `if 发现异常 then 立即离开`（改对）。
   写成一张表放进注释，别散在代码里的几个 `if`。
3. **老字段 `result` 也认。** `then` 那个位置 2026-09-25 之前叫 `result`，
   改名时漏改的剧本会**静默变成空块**（不报错，画面上少一块）。
   `_if_panel()` 里那句 `if then_block == "": then_block = step.text("result")`
   就是为它留的，别删。

## 四、按结果分岔：`next_when`

一个节点演完之后可能该去两个地方，取决于玩家之前干了什么。
原来的机制里只有 `next` 和选项两条路，没有这个。

```json
{
  "id": "again_day",
  "next": "again_dusk",
  "next_when": {
    "if": { "var": "gate/saved_a", "op": "==", "value": false },
    "next": "market_dusk"
  }
}
```

- **判在 `next` 之前**：条件满足就走它，否则才用 `next`
- 条件那套和 `Actor` / `Portal` 的 `if` 一模一样（`Condition.from_dictionary`）
- **写不全（缺条件或缺目标）就当没写** —— 别让半生不熟的东西留到运行时才炸
- 推进器走的是 `StoryRuntime` 里的 `node.resolved_next(flags)`

### ★ 别用「复刻一份对话」来分岔

两条出口**走同一个节点**（对话一个字不差），分岔放在**对话之后**。

策划明确说过：
> 「这个与老人两次委托不同，是单纯的回溯到前面的剧情节点！！！」

老人那两次委托是**复刻**（两份数据里写一样的话），那是特例。
IF 这边的"重演"是**回溯** —— 复用同一个节点，别复制。

理由是复刻那份要同步：改一句台词得记着改两处，迟早漏。

## 五、四种图各用在哪

素材在 `art/ui/place_*.png`（214×214，方块本体 170）。策划专门明确过：

| 图 | 用在哪 |
|---|---|
| `place_locked`（禁用） | **空着、不能用的格子** |
| `place_normal`（常态） | **待选列表里能拿的块** |
| `place_hover`（悬停） | **正在被拖着走的** |
| `place_active`（选中） | **已经放到位置上的**（`if` / `then` 那两格） |

**判断逻辑在 `IfPanel.block_state()`** —— 那是个纯函数、能断言。
别在 `_place_block()` 里另写一套。

## 六、踩过的坑

按时间顺序。**每一条都真发生过。**

1. **`if` 后面的引号只给了一半** —— 看着像单引号。`SEG_FIXED` 里两端都得有。
2. **先问宽度再设文字** —— `get_minimum_size()` 是照**当前** `text` 算的，
   顺序反了位置整个错位（引号跑进方块里、最后一段看不见）。
   **先设文字，再问宽度。**
3. **框底用九宫格装不下** —— 素材四角要 96 源像素，上下各 96 = 192，
   而视口只有 180 高。比例正好一致，整张等比缩放就行，别硬上九宫格。
4. **框的显示比例必须和素材一致** —— `BOX_SIZE` 取 282×153，
   素材是 1048×568（≈1.845）。不一致的话整张缩放会把描边压扁。
5. **空格子和"能拿的块"画成一个样** —— 玩家看不出哪个格子是空的。
   四张图各司其职（见第五节）。
6. **拖动中不换图** —— 看不出正在拖的是哪一块。
7. **块名的位置** —— 素材包 README 建议"方块下方放选项名"，但那是给
   竖排写的。四个横排时名字放下面会挤成一长条，**写进方块里**。
8. **锚点索引算错** —— `_blank_at` 里每个 `i` 都 `append`（固定段塞 `ZERO`），
   变成五个元素；而 `_slot_at()` 按「第 0 个是 if、第 1 个是 then」取 ——
   取到两个 `ZERO`，块全被当成"没位置"藏起来。**固定段不记锚点。**
9. **确定按钮画在 `_draw()` 里** —— Godot 里**父节点的 `_draw()` 永远画在
   子节点之下**，而框底是子节点，于是按钮被半透明地压住。
   **用真子节点**（`Panel` + `StyleBoxFlat` + `Label`）。
10. **`draw_string()` 从基线画** —— 拿 `get_string_size()` 估偏移会偏，
    字顶着框的上边缘。**要居中就用 `Label`。**
11. **确定按钮的 y 贴框底** —— 而四格是垂直居中的，差了一截。
    两处用同一个 y。
12. **确定按钮贴着右边框** —— 框底那张素材自己带一圈外留白，
    按 `PAD.x` 摆看着还是贴边。往里收（`CONFIRM_RIGHT_PAD`）。
13. **面板收鼠标之后关不掉** —— `mouse_filter` 从 `IGNORE` 改成 `STOP`
    才能拖，但收进来之后背后那套「点一下继续」就够不着面板了 → 卡关。
    **收尾只能靠「确定」按钮。**
14. **只拦了下面四格，没拦两个块位** —— `_begin_drag` 只看了 `_states`，
    而 `if` / `then` 那两格不在四格里，照样能拽。
    **`set_read_only()` 两条路都要拦**（`_begin_drag` + `move_to_slot`）。
15. **只判了 `then` 位** —— 把答案拖到 `if` 上、`then` 没动就蒙混过关。
    **「玩家摆得对不对」要把所有能拖的位置都算进去。**
16. **布局第一次算不准** —— 症状是「进来时文字偏位，出去再进一次就正」。
    首次算宽度时字体还没就绪。**`call_deferred` 补一遍**，
    用一个标记挡住第二次（不然 `_refresh` 自调就是死循环）。
17. **出口接错，卡死在框里** —— 两条出口都该往下走，结果一条绕回了自己。
    **测试抓不到这个**：数据上完全合法。改完跳转跑
    `python tools/show_story_chain.py <事件名>` 看一眼。
18. **把"重演"做成了复刻** —— 见第四节，策划连着纠正两回。
19. **给节点加了新字段忘了加白名单** —— `check_data.py` 的 `NODE_KEYS`
    会报「不认识的字段」。**加字段时两边一起加。**

## 七、设计上的几条规矩

1. **块的位置是内容说了算，不是外部状态说了算。**
   空格子 = 禁用图，有内容 = 常态/选中图，正拖着 = 悬停图。
   `set_slot_state` 只用来"额外禁用某一格"，不参与显示。
2. **判定抽成纯函数**（`IfPanel.judge()`）。夹在协程里测试就够不着 ——
   「什么都不做按确定就能往下演」那种毛病就是这么漏过去的。
3. **合规组合写成表放进注释。** 散在代码里的几个 `if` 早晚有人改坏一条。
4. **老字段兼容要留着。** 改名会让漏改的数据静默变空值，不报错。
5. **拿不准就去问。** 这个机制策划纠正过五回以上，每一次都是我"想当然"：
   复刻 vs 回溯、`if` 位能不能动、四种图各自的用处、循环是什么意思、
   确定按钮该在哪。**读原话，别读自己脑子里的版本。**
