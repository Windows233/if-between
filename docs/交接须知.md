## 五、踩坑记录（每条都是真踩过的，按要命程度排）

1. **原策划案是 AI 生成的，多处作废。** 逻辑解谜、因果债、悖论怪物、「玩家编写规则」
   全部不做；「不操控角色」整句作废。以 `开发纪要.md` 第九节为准。
2. **`enter_map()` 是从磁盘重读 JSON 的。** 在内存里改地图数据再 `enter_map` 等于白改；
   要验内存改动得用 `map_view.build(def, flags)` 重建。
3. **`git fetch` 不支持断点续传**，被掐掉就从零开始；**别把 fetch 挂后台**
   （沙箱后台没有网络，会一直挂着不动）。大包同步一律「对方给包 + 本地拉」。
4. **推送被拒（non-fast-forward）时不要急着 fetch。** 可以只推新分支：
   `git push origin HEAD:refs/heads/<分支名>` —— 纯上传，一个字节不用往回拉。
5. **别 `git add -A` 一把扫。** 这个工作区有时压着别人没提交的改动，一锅端会卷进去。
   只 add 你自己的路径。
6. **物件的 `decor`（只装饰）会切断剧情入口**：勾上之后它不参与交互，挂着的剧情再也触发不到。
   **数据完全合法，`check_data` 查不出来。** 编辑器为此加了拦截，手改 JSON 时要自己小心。
7. **旧地图的 `walls` 是地图级平铺的一张表**，挪旧物件时要检查它底下的墙。功能分支已支持物件局部 `collision`，移动/复制时会跟随；启用局部碰撞不会自动删除旧墙，正式地图尚未迁移。
8. **遮挡有两种做法别混**：`overlay`（前景层，整张拉伸、恒在角色之上）
   vs `cover` 物件（按 `cover_y` 基线切换前后）。判据：人只会在它前面走 → 前景层；
   人前后都会站 → 遮挡物件。
9. **不要另抄一份判定常量。** 可走判定只有一个来源 `core/walk_grid.gd`
   （`FOOT_HALF` / `FOOT_UP` / `step`）。以前 `test_walkable` 抄了一份 `FOOT_SIZE`，
   一路绿着可真机走不进去。编辑器的「可走格」「脚底框」也是直接调它。
10. **测试里别钉死坐标和数值。** 位置是策划随时在编辑器里调的，钉死就一调一红。
    判据要写成「跟着数据走」：出生点跟 `def.spawn_point()` 比、遮挡基线按有效基线算、
    传送口按「成对 + 带条件」找。（2026-09-27 一次就红了 7 条。）
11. **一次性开关别留在代码里**（`debug_start_map`、`skip_opening`、`debug_load_slot`），
    验收完必须关回空串 / false。历次都记在纪要里。
12. **文档别拿句子当锚点插小节。** 我用字符串替换往操作说明里插过两次，
    把章节顺序搞烂了两回。改结构要按标题切块重排。
