# 地图编辑器重制方案

> 状态：2026-10-23，本批非剧情编辑功能已接入唯一插件分支 `feat/map-editor`，对应游戏运行时已上传 `main`。下文记录完成范围和使用边界；统一回归及真实界面检查见 `交接须知.md`。地图编辑师的归属审核与玩家验收另行进行。
>
> 分支边界：`main` 拥有地图、素材和全部游戏运行时；唯一插件分支为 `feat/map-editor`。`feat/map-editor-groups`、`feat/editor-overlay-ui` 已在上批合并并删除，其他协作者的分支不在本批清理范围。正式地图迁移仍须逐图审核。

## 一、目标与用户

重制目标不是给现有 JSON 面板继续堆按钮，而是把它发展成面向场景制作的可视化工具，让不熟悉坐标、JSON 和引擎节点的创作者也能摆放对象、配置交互、检查场景并安全保存。

主要用户分三类：

| 用户 | 主要工作 | 主要工具模式 |
| --- | --- | --- |
| 普通创作者 / 策划 | 放置家具、NPC、门和调查点；配置交互；复制重复对象 | 场景对象模式 |
| 地图编辑师 | 划定地图级墙体、地形阻挡、可走区域、复杂通道和落点 | 碰撞与导航模式 |
| 剧情作者 / 演出编辑师 | 本批配置地图触发区域并绑定现有事件；节点分支与演出编辑暂缓 | 地图触发器；后续剧情模式 |

三个模式共享地图、对象标识和预览环境，但各自提供聚焦的工具与权限。地图级碰撞可以由专门编辑师负责，不应迫使普通创作者先理解整张地图的空气墙。

## 二、当前问题与保留项

以下为重制启动时的盘点；已落地能力与剩余工作以第九节的实现状态为准。

当前编辑器已经能在底图上编辑墙、传送区、Actor、出生点、前景遮罩和可走格，也复用运行时的 `WalkGrid`。这些能力和现有地图数据读取、验证逻辑应作为重制基线，而不是无条件推倒重写。

当前数据职责分散：物件用 `rect` 表示；交互可另设 `reach`；部分物件的碰撞靠地图级 `walls`；另有 `solid` Actor；渲染遮挡由 `cover`、`over` 与手动 `cover_y` 决定。编辑器因此没有一个“物件实例”能完整表达并携带它的视觉、碰撞、交互和排序属性。

重制前的体验缺少可复用物件库、实例复制粘贴与批量编辑、多选与图层组织、完整撤销重做、面向新手的属性解释、触发器到剧情的联动，以及基于真实地图渲染的预览和系统化校验。本批状态见第九节。

保留既有剧情分支和演出数据的语义。当前剧情是带分支的节点，每个节点含有序 `stage` 指令；编辑器应先可视化既有结构，不另造一套运行时剧情格式。

## 三、核心概念

### 3.1 场景

场景由底图、可选视觉图层、场景对象、地图级碰撞、出生点、出口/传送区域和触发器组成。底图允许继续使用完整手绘背景；非交互且无需独立排序的装饰可烘焙在底图中。

建议编辑器提供逻辑图层：背景与地面、场景对象、前景遮挡、地图碰撞、出口与触发器、演出标记。图层可见、锁定、隔离，并支持排序；图层是编辑组织方式，不意味着每个逻辑层都必须是一张图片。

### 3.2 物件模板与实例

模板（可复用物件定义）保存默认属性；实例保存场景位置、朝向、缩放、实例 ID 和必要的局部覆盖。实例可复制、粘贴、拖拽复制、成组、对齐和批量修改。复制应生成新实例 ID，但保持交互定义和模板引用。

模板/实例默认属性至少包括：

| 属性组 | 内容 |
| --- | --- |
| 外观 | 贴图或多部件渲染、逻辑原点、脚底锚点、默认渲染图层、透明预览 |
| 排序 | 排序模式、排序参考线来源、可选手动偏移、前后拆层/恒在前景模式 |
| 碰撞 | 零个或多个局部碰撞形状、启用状态、碰撞类别；形状相对物件原点存储 |
| 交互 | 是否可交互、交互形状或范围、触发方式、显示名、默认剧情/动作绑定 |
| 编辑辅助 | 分类、标签、缩略图、模板版本、默认吸附/摆放方向 |

实例自身可覆盖少量需要逐件变化的字段，例如显示名、交互绑定、状态条件、局部碰撞/交互形状启用。覆盖应在检查器中明确标记，并可恢复模板默认值。不要把所有实例差异强行写回模板。

### 3.3 碰撞的两级职责

- **物件局部碰撞**：属于桌子、书架、柜台等对象模板或实例，随物件移动、复制和变换。普通物件的碰撞编辑可由模板作者提供默认值；地图编辑师按地图需要检查/微调。
- **地图级碰撞**：属于场景本身，用于墙体、边界、地形、无法归属单个对象的建筑结构、窄通道等。由地图编辑师使用专用模式绘制和维护。
- 运行时最终阻挡集合由“活动物件的局部碰撞 + 地图级碰撞”组成。不得因为物件自带碰撞而再隐式生成重复的全图空气墙。
- 玩家脚底碰撞尺寸仍由 `WalkGrid`/玩家运行时定义提供唯一口径。编辑器的可走预览必须调用同一份判定。

交互形状与碰撞形状可以不同，例如桌子实体占地窄，交互区向玩家可站立的一侧延伸；但二者都属于桌子对象的局部属性，随桌子一起移动。允许交互形状与碰撞重叠，重叠时通过交互优先级、对象选择提示和玩家朝向消歧，不用要求编辑师在地图上另画一条无归属空气墙。

## 四、自动排序与遮挡规则

### 4.1 默认规则

默认遮挡基线取**指定局部碰撞箱的上边缘**，并将玩家脚底 Y 与该场景坐标线比较：玩家脚底在基线北侧时物件绘制在玩家前方；在基线南侧时玩家绘制在物件前方。该规则把已有碰撞几何复用为排序依据，不需要每个实例再手画一条线。

每个模板必须明确排序参考碰撞形状 ID，不能在有多个碰撞箱时隐式猜测“哪个上边缘”。编辑器应在画布上显示自动基线，并能预览玩家从物件后方走到前方时的层级切换。

### 4.2 手动调节入口

保留模板级和实例级的手动排序偏移。默认偏移为零；需要修正美术边缘、阴影或特殊摆放时再启用。属性面板应显示“自动：碰撞箱上边缘”或“手动：自动基线 + 偏移”，并提供恢复自动按钮。迁移旧 `cover_y` 时转换成相对自动基线的偏移，先在预览中核对，再保存。

### 4.3 复杂对象

一条 Y 基线不能表达所有几何关系。本批在物件属性卡接入 `visual_parts` 多部件编辑，每个部件有 ID、贴图、相对物件左上角的矩形和排序偏移。层可选 `back`（固定后层）、`auto`（按物件基线加部件偏移排序）、`front`（固定前层）。部件仍属于同一物件，沿用该实例的碰撞、交互与模板关系。

树冠、柜台两侧、拱门等可拆为多个部件分别设置前后关系；固定背景仍可保留烘焙做法。本批不提供局部遮挡多边形、自动抠图或通用 Sorting Group 编辑器。`main` 运行时已接入部件解析、分层与贴图变换，并通过独立游戏回归及插件整合验证；实际地图的遮挡效果仍需逐图试走审核。

不要把逐像素自动抠图作为通用必需流程。完整背景和局部独立素材可以共存；只有需要独立放置、状态变化或前后穿插的内容才要求拆件。

## 五、编辑器工作流与界面

当前主编辑页为 Godot 顶部「IF 场景」，本批入口如下：

- **顶部**：地图选择、新建/导入物件、适应画布、保存、当前布局试走；地图管理、显示、选择与尺寸、排布与模板按需展开。
- **左侧「场景 / 素材」**：嵌套场景树、隐藏/锁定、定位与素材拖放。组可拖到另一组内，行间拖放改变同级顺序；树顺序属于编辑组织，不改变运行时 Y 排序。
- **左侧「工具」**：吸附网格、步长、显示层隔离、各层锁定，以及「场景检查 / 触发 / 试走设置…」。该窗口分为「校验与迁移」「事件触发区域」「试走状态与地图比较」「快捷键」四页。
- **中央**：缩放平移、空白处框选、Shift 追加/Ctrl 切换选择、Alt 拖拷、网格吸附与八柄缩放。矩形触发区域由工具窗口配置、从当前矩形选区取范围并在画布定位。
- **右侧物件属性卡**：原有外观、碰撞、交互与排序；新增「视觉部件与变换」和模板来源、版本、覆盖状态、更新/恢复预览。翻转、90° 旋转和等比缩放同步调整局部几何。
- **检查与定位**：错误/警告列表在「校验与迁移」页，点击当前图的具体对象问题可定位。底部保留状态提示。剧情指令列表和时间轴均暂缓。

新手预设工作流：从模板库拖入对象 → 自动对齐脚底点/网格 → 复制排布 → 在属性面板选择“可交互”并绑定动作 → 运行时预览 → 一键验证。默认只显示常用属性，高级碰撞与排序覆盖放在展开面板。

必须具备：撤销/重做、保存前校验、未保存变更提示、重复对象快捷复制、选择被遮挡对象的场景树入口、锁定底图/锁定已完成图层、可视化错误定位、稳定对象 ID、可恢复的草稿与自动备份。

## 六、剧情与触发编辑扩展

### 6.1 地图触发器

本批触发器通过左侧「工具 → 场景检查 / 触发 / 试走设置… → 事件触发区域」配置，写入地图 `triggers`。当前支持矩形；点使用 `1 × 1` 矩形表示，多边形不在本批范围。每项有唯一 ID、矩形、现有事件 ID、启用开关、触发方式、`once` 和条件。

| 方式 | 配置含义 |
| --- | --- |
| `enter_map` | 进入地图时检查条件并请求事件 |
| `enter` | 玩家进入矩形区域时请求事件 |
| `interact` | 玩家在区域内按交互键时请求事件 |
| `click` | 点击区域时请求事件 |

「本存档只触发一次」对应 `once`；运行器按地图 ID 与触发器 ID 将标记写入世界状态，随存档持久化，切图仅清理局部进入边缘，不清已触发标记。新游戏随世界状态重置，事件启动未被接受时不消耗一次性标记。条件沿用现有 `Condition`，表单接受 `var/op/value`、`exists`、`all`、`any`、`not` 的 JSON，留空表示无条件。此处只绑定已有 `data/events/` 事件，不创建剧情正文。

编辑器已接入增删、绑定、矩形数值/选区取框、画布定位和条件检查；`main` 运行时已接入四种方式与世界状态记录，并通过事件执行和真实存读档联动测试。现有布局试走只检查交互目标，不执行事件，不能用它确认剧情已触发。

对象交互可以直接引用一个或多个剧情/动作入口；区域触发不必伪装成家具。触发器与可交互物件可有关联 ID，但运行时触发语义清楚地区分，避免一个对象的 `decor` 等显示字段意外切断剧情入口。

### 6.2 剧情节点视图

**本批明确暂缓剧情脚本与演出编辑。** 以下均为后续规划，不属于本批完成项。物件现有单句旁白与多句对话编辑保留。

后续可先做现有剧情结构的可视化管理：节点列表/图、节点搜索、入口标识、条件分支与选项连线、悬空引用和不可达节点检查。保留现有 JSON/解析/校验作为数据契约。

选中节点后，以可排序指令列表编辑现有 `stage`：对话、淡入淡出、移动玩家/NPC、摆放/移除临时角色、音乐/音效、图片、镜头焦点、等待等。每条指令使用专用表单和地图坐标拾取，不让作者手写坐标字段；列表支持复制、禁用预览、播放到此步和定位引用。

时间轴作为后续演出视图：按角色、镜头、音频、画面效果分轨显示时长型动作；对白停顿/分支等待仍由剧情节点语义控制。不要把条件分支和整段逻辑塞进线性时间轴，也不要为了可视化重写现有剧情运行时。

## 七、数据与兼容策略

重制按“编辑器内部模型 + 明确序列化适配层”推进。第一阶段优先继续读现有 `data/maps/*.json`；新能力可先增加版本化字段或伴随资源定义，但须保持旧地图可加载。正式确定新 schema 后提供一次性迁移器、迁移报告、备份和可重复验证，不要求人工手改地图 JSON。

当前继续使用地图 JSON 和 `data/map_objects/` 模板 JSON。`editor_groups` 的 `parent` 与 `editor_tree_order` 保存嵌套关系和树顺序，供编辑器使用；`visual_parts` 与变换是物件数据，`triggers` 是地图数据，需要对应游戏运行时支持。

模板兼容旧快照格式，新增格式版本 `version: 2`、内容修订号 `template_version` 和单父模板 `extends`；库 API 的 `parent` 参数写入 `extends`。缺失父模板、继承循环或非法模板会阻止放置/更新。实例记录 `source_template`、`source_template_version`、`source_template_defaults` 默认快照；更新时比较旧默认、实例现值和新默认，保留实例覆盖。检查器先展示差异再确认；恢复勾选字段/全部默认是明确覆盖实例的另一个入口。缺少可信快照的旧实例须先「建立安全基线（保留现状）」。

源模板更新与地图实例更新分别确认；更新模板文件不会静默重写已放置实例。源模板文件的写入不属于地图撤销历史，实例更新可整步撤销，之后仍须保存地图。

迁移旧字段原则：

- 旧 `walls` 保留为地图级碰撞，不猜测并自动归属到附近物件。
- 旧 `solid` 对象转为对应对象的局部碰撞候选；需检查是否与地图级墙重复。
- 旧 `reach` 转为对象局部交互形状。
- 旧 `cover_y` 转为排序偏移；旧 `cover`/`over` 转为排序模式候选。
- 旧 `overlay` 保留为场景前景图层；不得自动拆分透明 PNG。
- 未能确定的对象在迁移报告中列为待人工确认，不做静默猜测。

## 八、校验与验收

编辑器校验至少覆盖：缺失资源、重复/缺失对象 ID、模板不存在、交互绑定无效、触发器引用不存在、无效碰撞形状、排序参考碰撞不存在、实例覆盖异常、出生点落在阻挡区、可走区域断开、地图出口目标不存在。

核心验收场景：

1. 拖入书桌模板，碰撞、交互和自动排序线随实例出现；移动/复制后属性和相对关系保持正确。
2. 玩家从桌后走到桌前，按碰撞箱上边缘自动切换遮挡；实例调整偏移后只影响该实例，恢复自动后回到模板规则。
3. 碰撞编辑师修改桌子局部碰撞后，运行时物理与可走预览一致；地图级墙仍可单独编辑且不重复挡路。
4. 重复摆放椅子、摊位或装饰组，可多选、复制、对齐、批量调整；撤销重做完整恢复数据与画面。
5. 矩形触发区域可绑定现有事件；分别在游戏中核对四种触发方式、条件、启用状态，以及一次性触发后离图重进和存读档的表现。剧情节点、演出走位拾取另列后续验收。
6. 运行时预览与正式游戏使用同一渲染、碰撞和交互实现，避免编辑器自画一套但游戏表现不同。

试点地图建议选择：集市（多对象重复与昼夜共享布局）、图书馆（整图背景与墙体前景层）、门卫室或卧室（家具交互、局部碰撞和前后遮挡）。至少覆盖一张室外大场景和一张室内房间后再决定 schema。

## 九、分阶段实施

### 本批非剧情功能状态（2026-10-23）

既有物件局部碰撞/交互、自动基线与偏移、复制排布、草稿/自动备份、素材放置、隐藏/锁定和独立 `World2D` 试走继续保留。本批新增入口如下，均以当前源码接入状态记录：

| 能力 | 已接入的范围 | 验证与使用边界 |
| --- | --- | --- |
| 嵌套层级 | 组的父子关系、组/物件拖入与同级排序、完整组复制时重建成员与父组关系 | 嵌套复制、ID 引用、整体删除和撤销纳入统一回归；树顺序不决定渲染层级 |
| 画布工作流 | 吸附网格与可调步长、框选/追加/切换选择、Alt 拖拷、层隔离/锁定、翻转/90° 旋转/缩放 | 多选与受保护对象纳入回归；各物件以自身中心变换，几何同步 |
| 多部件外观 | 属性卡编辑 `visual_parts` 的 `back/auto/front`、贴图、局部矩形和基线偏移 | 游戏真实 MapView 核对分层与旋转翻转；遮挡多边形未做 |
| 模板 | 筛选浏览与拖入、单父继承、版本和默认快照、实例覆盖标记、更新/恢复的预览确认；源模板父级/分类/标签更新 | 跨地图实例分别载入更新；旧实例安全基线和过期/失败保护纳入回归 |
| 校验 | 当前布局的资源/引用/几何/模板检查、出生点阻挡、导航连通和出口可达性问题；列表定位 | 超大地图可能跳过导航并警告；状态条件仍需分别试走 |
| 显式迁移与报告 | 同图多物件墙归属计划、整批预检/差异/撤销；所选地图或 manifest 的只读报告、JSON/TXT 导出 | 预览不触发保存，只有保存请求进入闸门；正式地图归属与逐图应用由编辑师审核 |
| 试走与比较 | flags 值/类型、出生点、范围显示；当前未保存布局与另一地图并排只读比较 | 不执行剧情，不代替游戏流程；不同地图比较侧读取磁盘版本 |
| 快捷键 | 当前画布快捷键重绑、冲突提示、Esc 取消捕获、恢复默认、本机保存 | 只接收编辑器画布输入，不改游戏按键或系统按键 |
| 地图触发器 | 插件矩形配置/绑定/定位与取选区；main 运行时四方式、条件与 once 世界状态记录 | 真实主场景验证存读档与新游戏清理；预览不执行剧情 |

- **尺寸口径**：物件源图按背景像素比例换算到地图单位；新建地图的默认尺寸等于背景原图像素，因此新图为 1:1。已有小尺度地图保留原尺度，不直接套用一像素一个地图单位。
- **编辑状态边界**：隐藏/锁定按地图与物件 ID 保存在本机配置，不进入地图 JSON、运行时或地图撤销历史。隐藏不移除游戏碰撞/交互；复制出的新实例默认显示且未锁定。嵌套组和树顺序另写入地图编辑器元数据，不能当作渲染前后顺序使用。
- **迁移边界**：墙必须由编辑师明确指定，不能由重叠自动推断；共用建筑墙仍保留地图级。当前批量迁移针对一张图内的多个物件，跨地图报告是只读审阅，不是跨图一键落盘。
- **明确暂缓**：剧情节点编辑器、节点分支图、`stage` 演出指令编辑、时间轴、演出坐标拾取与分步播放。物件单句/多句编辑保留，事件触发区域只引用已有事件。
- **验收边界**：测试证据见交接与开发纪要；自动回归不代表地图编辑师完成正式图归属审核、美术交付规范确认或玩家验收。

### 阶段 0：需求与素材审计

- **进度**：已有地图编辑器、运行时碰撞/排序与现有素材完成初步盘点；新增只读 `tools/audit_map_migration.py` 可输出逐图字段与问题报告，室内门卫室、室外集市昼夜的候选与人工检查项见 `地图编辑器-试点验收.md`。独立物件交付规范、试点模板与具体迁移清单仍待确认。

- 盘点现有地图、Actor 字段、墙、前景层、运行时排序和交互案例。
- 将物件分为静态烘焙、可复制放置、可交互、需局部碰撞、需复杂遮挡几类。
- 与美术确认独立物件的逻辑原点/脚底锚点、透明边界、分层例外和昼夜配对规范。
- 产出试点对象模板草案与旧数据迁移清单；不改动正式地图数据。

### 阶段 1：对象模板与画布基础

- **进度**：既有物件工作流已扩展嵌套层级与排序、框选/网格/拖拷/变换、多部件、模板继承/版本/实例覆盖更新，纳入统一回归。室内外正式图的碰撞归属仍由地图编辑师审核。

### 阶段 2：碰撞、自动排序与迁移试点

- **进度**：既有局部碰撞、局部交互与自动基线保留；显式批量墙归属、前后差异、跨地图/manifest 只读报告与导出、导航校验和定位已接入并回归。迁移预览与保存分开；正式地图逐图迁移仍须人工确认归属。

- 将物件局部碰撞纳入运行时、编辑器预览和可走格同一数据源。
- 默认排序基线取模板指定碰撞箱上边缘，添加模板/实例排序偏移与复杂对象分层。
- 为试点地图提供迁移器和差异报告；由地图编辑师审核局部/地图级碰撞重复。
- 通过后再扩大迁移范围。

- **进度**：矩形触发器配置与引用检查已接入，支持 `enter_map/enter/interact/click`、启用、条件与 once，真实主场景运行和存档联动已验证。剧情节点和演出指令编辑明确暂缓。

- **进度**：演出时间轴明确暂缓；本阶段中独立于剧情编辑的状态试走、出生点选择、两图比较、快捷键配置与跨地图审阅已提前接入本批。批量对象变体与团队协作系统未做。

- 在已有指令列表稳定后增加角色/镜头/音频/效果时间轴视图。
- 完成状态试走、地图比较、快捷键和多地图引用审阅的整合验证；批量对象变体另行规划。
- 评估团队协作锁定/合并体验；在确认多人同时编辑需求之前，不建设复杂的在线协作系统。

## 十、风险与暂不承诺项

- 单张合成底图无法可靠推断对象边界、脚底和局部遮挡关系；自动排序依赖明确碰撞箱/排序锚点。
- 一条排序线不能解决对象内部的局部穿插；复杂对象需要拆层或分区遮挡数据。
- 自动把现有 `walls` 猜成家具碰撞可能改变窄道可达性，迁移必须可视化并人工审核。
- 直接引入通用地图格式可能无法表达现有剧情交互、存档状态和美术背景工作流；先借鉴概念，不绑定特定第三方编辑器。
- 可视化剧情编辑器容易演变成完整脚本 IDE；优先复用现有节点、条件、选项和 `stage` schema，按阶段交付。
- 本方案不规定所有美术都要拆成独立物件，也不要求每个装饰对象拥有碰撞或交互。

## 十一、参考工具与借鉴边界

- Unity：对象组件、Prefab/实例覆盖、Pivot/Sorting Group；借鉴“模板定义 + 场景实例”的心智模型，不照搬其通用 3D 场景层级。
- Tiled：对象模板、自定义属性、多种对象形状、分组图层与批量场景编辑；借鉴轻量对象编辑和图层可见/锁定。
- LDtk：图层职责、实体与场景数据组织；借鉴分层组织，不把网格关卡约束带入手绘大背景。
- RPG Maker：地图事件触发和命令列表；借鉴触发器可视化与快速上手，不把有限的排序优先级当成复杂 2.5D 遮挡解法。
- Unity Timeline：多轨演出编排；仅作为阶段 4 的可选视图，不替代剧情分支图。

后续扩展与正式地图迁移前，仍须确认试点对象、排序参考规则、墙归属清单与美术交付最低要求；本批实现不代替这些审核。
