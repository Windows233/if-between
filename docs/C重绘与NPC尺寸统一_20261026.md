# C 重绘与 NPC 尺寸统一

2026-10-26。基于本地 `c8987b5`，工作分支 `codex/c-sprites-npc-scale-20261026`。本轮只本地提交，未推送。

当前侧走以[C主角同款侧走](C主角同款侧走_20261026.md)为准：八相位版经用户反馈动作偏僵硬，已按主角实际姿势重画四帧，8FPS；第1/3/idle_side一致。以下为初次重绘的历史记录，NPC统一尺寸规则继续生效。

## 这次替换了什么

C 的旧走路帧只有 64×64，而主角是 258×360；旧剧情又多处把 C 高度写成 32，主角为 45。旧 C 正面实际可见高度约 26.5，新版与主角正面站姿均为 43.25 逻辑像素，解决了“既糊又小”的两个来源。

使用内置 **imagegen** 重新绘制 C，保留银白头发、灰眼睛、灰围巾、深色长外套及靴子；按主角的像素细节和头身比例制作。源图由模型绘制完整步态，导出工具只切帧、等比缩放和对齐，没有用旧 64 像素帧放大冒充重绘，也没有用程序摆动身体拼假走路。

## 程序直接调用

保持 `res://art/npc/c` 目录调用方式，已有剧情与追兵会自动使用新版。所有帧都是 **258×360 透明 PNG**。

| 文件 | 对应内容 |
| --- | --- |
| `art/npc/c/idle_down.png` | 正面站姿 |
| `art/npc/c/idle_up.png` | 背面站姿 |
| `art/npc/c/idle_side.png` | 向左侧面站姿；向右时镜像 |
| `art/npc/c/down1.png`—`down4.png` | 正面四步态 |
| `art/npc/c/up1.png`—`up4.png` | 背面四步态 |
| `art/npc/c/side1.png`—`side8.png` | 向左侧面八步态；向右时镜像 |

正背面每秒8帧，侧面每秒16帧，均为一轮0.5秒。停下使用独立站姿，避免站着仍保持迈腿姿势。剧情行走及后段追兵均按方向选择对应动画；C 横向移动时正确使用侧面。A 只有静态侧站和蹲姿，保留其原有淡出与姿势行为。

`art/npc/c/c.png`、`c小人.png` 是历史参考原件；正式站姿及行走调用上表 19 帧。生成源表、提示词和切帧范围保存在 `art/npc/c/source/`，完整来源、散列和帧序见 `art/catalogs/c_redraw_20261026.json`。需要重新导出时使用 `tools/build_c_sprites.py`，再执行 Godot 资源导入。

## NPC 大小规则

- 正式人形 NPC **A、B、C、老人**统一使用 `Player.DISPLAY_HEIGHT`，当前为 **45**。各地图继续共用原 `player_scale` 和相机投影；没有改变地图比例来迁就角色。
- 操场受困/获救 C、校门等待 C、图书馆与追逐 C 使用相同标尺；B 原先的 40/42 也归一为 45。
- 旧剧情及旧存档输入 32/40/42 时，创建入口自动归一，后续快照保存 45；脚底坐标保留，不反复积累缩放。
- 商店原有无贴图 B 占位也改为现有 B 正面图，画框高度 45，原脚底与世界碰撞位置保留。
- 统一的是人物基础标尺。蹲姿、头发留白和服装轮廓保留自然差异，不把蹲着的人强拉成站立高度。黑猫、黑雾与非人物特效不套人形规则。
- C 新帧从方形改为与主角相同的长方形，救援束缚层已按新画布分别对齐宽高，实际截图已核查。

旧演出文件中 C=32、B=40/42 的身高记载被本规则覆盖；剧情文字与角色身份沿用。

## 验证

- Godot 资源导入与数据检查通过：14 图 / 32 剧情 / 7 结局 / 11 物品。
- 游戏全量 **4970/4970**。新增验证覆盖 15 帧尺寸、三方向各四张不同步态、独立站姿、左右朝向、旧存档尺寸迁移、脚底坐标及束缚对齐。
- 真实 GPU 同框核查 A/B/C/老人均为 45；操场和校门的实际 C 均为 45，束缚画布为 258×360。
- 换图后从第二次闪避成功开始，真窗口自动试走追逐、教室抛币、夜市 B、委托屋至 End7 通过。第一章真窗口烟测通过。
- 这不是整章人工通关证据；新风格和步态仍可按团队试玩反馈调整。既有负面测试/引擎诊断保留。
