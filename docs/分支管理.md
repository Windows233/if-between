# 分支职责与整合规则

2026-10-22 按策划要求整理：地图是游戏内容；独立分支承载的是可选 Godot 地图编辑插件。

| 分支 | 职责 | 不应只留在这里的内容 |
| --- | --- | --- |
| `main` | 可运行游戏、地图 JSON、美术与音频、剧情、公共数据结构、物理与寻路、数据检查、游戏测试 | 无 |
| `feat/map-editor` | `addons/if_map_editor/`、插件启用配置、编辑器操作与迁移工具、编辑器专用测试和说明 | 游戏功能、地图、美术、剧情与运行时兼容改动必须先进入 `main` |

`main` 不包含 IF 地图编辑插件，也不预加载插件测试。游戏读取地图不依赖编辑器是否安装；物件局部碰撞、局部交互范围、自动遮挡与地图校验属于游戏数据协议，保留在 `main`。

## 日常操作

1. 改游戏、地图或素材，在 `main` 上检查当前状态并提交自己的路径。需要图形化编辑时使用插件分支，保存后将实际改动的游戏路径单独送回 `main`，不可把插件目录一起合回。
2. 改编辑器，在唯一的 `feat/map-editor` 上操作。如果发现需要修改 `core/`、`scenes/` 或游戏数据检查，先将相应运行时改动及不依赖插件的测试提交到 `main`，再同步进插件分支。
3. 插件分支从 `main` 同步游戏更新；两者的 `data/`、`art/`、`core/`、`scenes/` 应保持相同。主测试入口 `tests/run_tests.gd` 也保持相同。
4. 游戏测试运行 `tests/run_tests.gd`；安装插件的分支另运行 `tests/run_map_editor_tests.gd`、编辑器探针与试走检查。
5. 只推明确的目标分支。清理旧分支之前，检查祖先关系、独有提交和最终文件内容，不能靠名字判断是否过期。

当前 `addons/godot_mcp/` 是既有开发连接工具，本次只抽离 IF 地图编辑插件，未改动该连接工具。
