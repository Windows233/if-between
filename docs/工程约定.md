# 工程约定与改动索引

> 这份文档只有一个目的：**加新东西的时候，不用先把旧代码读一遍。**
>
> 写代码、改代码之前先读它。设计与进度看 `开发纪要.md`。

## 一、分层与依赖方向

```
core/     纯逻辑。条件判定、世界状态、场景数据解析。禁止 import 场景、节点、UI。
data/     maps/ 场景定义，events/ 剧情；以后的表格也放这里
scenes/   地图、角色、入口
ui/       **代码**：对话框、选项菜单等界面逻辑
tests/    测试与截图工具
art/      **美术资源**，见下
audio/    音频资源，见下
```

**注意 `ui/` 和 `art/ui/` 不是一回事**：前者是界面代码，后者是界面用的图。

### 资源目录

```
art/
  portrait/          半身立绘（对话用），按角色分子目录
	protagonist/       主角
  sprite/            场景里的角色图（行走、待机）
  map/               地图底图
	room/              室内
	overworld/         大地图
  ui/                界面美术：按钮、面板、图标、边框
  fx/                特效素材
audio/
  bgm/               背景音乐
  sfx/               音效
  voice/             语音
```

**文件一律用英文小写加下划线命名。** 中文文件名在 Godot 里能跑，
但跨平台导出和命令行工具上容易出岔子，趁早统一。

美术给过来的中文名文件，拷进来时改成英文，并在 `docs/开发纪要.md`
的资源对照表里记一行「原名 → 新名」，方便对回去。

**依赖是单向的**：`ui/` `scenes/` 可以依赖 `core/`，反过来一律不许。

这条一旦破了，引擎就再也没法脱离编辑器测试，改一行要开一次界面。

判断方法很土但有效：`core/` 里的文件，`grep` 一下 `preload` / `load` / `get_node`，
出现就说明越界了。

## 二、文件的写法

1. **一个文件一个职责。** 文件名要能直接说明它是什么，不要 `utils.gd`、`helpers.gd`。
2. **文件头注释写三段**：这是什么 → 为什么这么设计 → 加东西时要注意什么。
   参考 `core/rule_engine.gd` 的开头。
3. **公开接口带 `##` 文档注释**，说清参数含义与返回值形状（尤其是 Dictionary 的键）。
4. **用静态类型**（`var x: int`、`-> bool`）。这样编辑器和工具链能直接给出提示，
   读代码的人和 AI 都不用靠推理。
5. **枚举 + 工厂方法**：新增一种块，加一个枚举值和一个工厂方法即可，
   不改调用方。见 `Condition` 和 `Action`。
6. **数据里不写魔法字符串**。变量名用 `StringName`，别在代码里散落 `"girl.mood"`。

## 三、规模红线

- **核心代码**单文件超过 **400 行**就开始考虑拆。
- **测试文件**放宽到 **1500 行**，超了按测试组拆成多个文件。
- 单个函数超过 **60 行**就考虑拆。
- `RuleEngine.run()` 是唯一允许长一点的地方（求值主干），但辅助逻辑必须外提。

当前行数（2026-09-21 第二轮整理后）：

| 文件 | 行数 | 说明 |
| --- | --- | --- |
| `scenes/main.gd` | 635 | **超红线**。剩下的是组装 / 切场景 / 交互 / 输入路由，彼此咬得紧，**别再往里塞** |
| `ui/dialogue_box.gd` | 569 | **超红线**。已拆出立绘与按钮条，再拆就是传引用游戏，见 16.3 |
| `tests/test_ending_save.gd` | 452 | 最大的测试组文件，测试放宽到 1500，没问题 |
| `ui/save_menu.gd` | 406 | 刚过线，暂时不动 |
| `ui/ending_gallery_panel.gd` | 362 | 图鉴面板 |
| `tests/test_rules.gd` | 363 | |
| `tests/test_menus.gd` | 340 | 标题 / 菜单 / 调度器 |
| `ui/title_screen.gd` | 314 | |
| `tests/test_gallery.gd` | 240 | 图鉴：记录 + 面板 + 跨存档 |
| `tests/test_presentation.gd` | ~230 | 面板高度 / 跳过已读 / 速度 / 动效 |
| `tests/run_tests.gd` | 40 | 测试入口 |
| 其余核心文件 | 都 < 350 | 安全 |

**测试文件已按组拆开**（`test_rules` / `test_map` / `test_dialogue` /
`test_story` / `test_ending_save`），公共工具在 `tests/test_harness.gd`。
**加用例记得登记进对应组的 `run()`，并留意总数变化** ——
总数掉了说明有用例没跑到，运行时报错会静默截断后面的断言。
跑无头测试记得带超时：脚本编译失败时 `quit()` 不会执行，进程会挂着。

**判断要不要拆，看的是边界清不清楚，不是行数。** 行数只是提醒你去看一眼。
`main.gd` 里剩下的（场景切换、交互、输入路由）彼此咬得很紧，
硬拆会变成「传一堆引用」的游戏，反而更难读。所以拆到 417 就停了。

## 四、测试约定

- 每条机制都要有对应测试。**加机制不加测试，等于没加。**
- 跑法见 `开发纪要.md` 的「怎么跑」。
- 测试里要包含**反面用例**：写错了会怎样。`test_unguarded_add_diverges` 就是这种。
- 不引入测试框架。少一个依赖，clone 下来能直接跑。

## 五、改动索引（要加东西先查这里）

| 我想做的事 | 动哪里 |
| --- | --- |
| 加一种比较运算符（如 `IN`） | `core/condition.gd`：`Op` 枚举 + `_compare()` |
| 加一种条件节点（如 `XOR`、`COUNT`） | `core/condition.gd`：`Kind` 枚举 + `eval()` + `to_text()` + `_collect_variables()` |
| 加一种动作（移动、生成/删除物品、改写规则） | `core/action.gd`：`Kind` 枚举 + `propose()` + `to_text()` |
| 规则的数据结构不够用 | `core/rule.gd`。注意 `Branch` 已支持任意多分支 |
| 改求值顺序、收敛策略、迭代上限 | `core/rule_engine.gd` → `run()` |
| 改冲突怎么判定 | `core/rule_engine.gd` → `_resolve_conflicts()` |
| 加一种悖论检测 | `core/rule_engine.gd` 新增 `_detect_xxx()`，结果推给 `result.paradoxes` |
| 想让首页面看到更多运行信息 | `core/rule_run_result.gd` 加字段，在 `run()` 里填 |
| 加一个房间 | `data/maps/<id>.json`，**不用动代码** |
| 出生点叫什么 | **`from_<从哪儿来>`**：从大地图进就是 `from_overworld`（委托店、集市都是），从卧室进是 `from_bedroom`。**换入口就要改名**，并且目标地图里得有同名出生点 —— 缺了 `check_data.py` 会报（集市 2026-09-24 重做时从 `from_desk` 改成了 `from_overworld`） |
| 加一段剧情 | `data/events/<id>.json`，再在角色的 `event` 里引用，**不用动代码** |
| 加一个 IF 选项或一个状态标记 | 剧情 JSON 的 `choices` 里加一条，**不用动代码** |
| 让某个选项满足条件才能选 | 给那条选项写 `if`，写法见开发纪要 13.3 |
| 加一种条件写法（比如 `contains`） | `core/condition.gd` 的 `from_dictionary()` 与 `op_from_text()` |
| 加一个 NPC 或可调查物件 | 在对应地图的 `actors` 里加一条，**不用动代码** |

| 让某个角色或连接满足条件才出现 | 给它写 `if`，写法见开发纪要 10.5 |
| 换大地图的背景插画 | 地图 JSON 的 `background` 填图片路径，**不用动代码** |

| 加一个结局 | `data/endings.json` 加一项，再在剧情节点上写 `"ending": "<id>"`，**不用动代码**。图鉴会自动多出一行 |

| 改菜单 / 标题的行为 | `scenes/menu_flow.gd`。`main` 上的入口只是转发 |

| 改对话框的观感（面板高度、按钮条、立绘） | 高度与流程在 `ui/dialogue_box.gd`；按钮条在 `ui/dialogue_buttons.gd`；立绘在 `ui/dialogue_portrait.gd` |

## 六、加一个新机制的完整流程

1. 先查上表，确定要动哪几个文件。
2. 改 `core/`，同时在 `tests/test_<主题>.gd` 里加用例（含反面用例），
   并登记进该组的 `run()`。
3. 跑测试，全绿再往下。
4. 如果引入了新的设计取舍，写进 `开发纪要.md` 的「待定」或「踩过的坑」。
5. 如果出现新的「要做 X 就动 Y」的对应关系，补进本文件第五节。

## 七、别做的事

- 别在 `core/` 里读 `user://` 或任何运行时路径。状态由外部塞进来，引擎只算。
- 别让 `RuleEngine` 直接产出画面。所有展示信息走 `RuleRunResult`。
- 别为了「以后可能要用」提前抽象。等第二个用例出现再抽。
- 别把规则写成字符串再解析。`Condition` / `Action` 是结构化对象，保持这样。
| 写 `_draw()` 画东西 | **写在能用它的那个类上。** `CanvasLayer` 没有 `_draw` —— 需要层号就**外面套一层** `CanvasLayer`，别反过来在它里面造一个会画的类（试过，内层类的 `_draw()` 不肯跑，划的线一条都没出来，开发纪要 55.2）。`Control` 挂在 `CanvasLayer` 下面时**锚点算不出尺寸**，`size` 要手动给，不然 `_draw` 画了也看不见 |
| 量 `Label` 的宽度 | **先设 `text`，再调 `get_minimum_size()`。** 它照的是 Label **当前**的文字 —— 先问后设拿到的是空的（或上一帧的），摆出来整个错位（2026-09-24 踩过两次：一次框比字窄、一次引号跑进方块里）。中文一字的宽度也**不等于**字号，所以别拿「字数 × 字号」估 |
| 加一条新的演出指令 | 三处都要动：`core/stage_step.gd` 的 `KINDS`（写必填字段）、`scenes/cutscene.gd` 的 `_perform()` 分派 + 实现、`tools/check_data.py` 的校验（可选）。**即时模式（`instant`）下不许等** —— 测试里没人点，等下去整段就卡住了 |
| 写 `caption`（屏幕正中那几行字） | `lines` 是**对象数组**：`[{"text": "第一行"}, {"text": "第二行"}]`。写成 `["第一行"]` 的话体检会报「那几行字全是空的」。它**自带 `wait_click`**，不用再跟一条等点击的指令（开发纪要 56.3） |
| 一扇门后面还有一段戏 | 别只用 `to`。给连接写 `"event": "事件名"` —— 按互动时演那一段，进门那步由事件自己 `goto`（`keep_story` 是开的，跨场景能接着演）。`validate` 认得这种写法（开发纪要 56.2） |
| 临时封住某扇门 | 给连接写 `"blocked_by": "flag名"` + `"blocked_text": "要说的话"`。剧本把这个 flag 设成真就拦住，人走不出去、只弹那句话；清掉就恢复。**和 `condition` 不是一回事**：那个是让连接整个消失（开发纪要 56.2） |
| 写「等时间 / 等补间」的指令 | **必须在 `instant` 下短路。** 测试依赖「`interact()` 之后整段同步跑完」—— 一 `await` 就把控制权让出去，后面几步根本轮不到，测试看到的是「演出停在半路」。`_time()` 会自己返回 0，但**自己写的循环和补间得自己判 `instant`**（2026-09-24 踩的，开发纪要 56.7） |
| 放一张 CG 图 | `{ "do": "image", "path": "...", "fill": true, "hold": 3.0 }`。`fill` = 铺满整屏（CG 是 16:9，拉满不变形；道具图别加它）；`hold` = 停几秒，**停的时候点左键 / 空格能提前翻过去**。要让它留着让对话框压在上面说，加 `"hide": false`，之后手动 `image_hide`（开发纪要 56.6） |
| 做「被打断」那种转场 | 用 `{ "do": "flash", "color": "white", "times": 3, "time": 0.16 }`。**别用 `glass`** —— 碎屏是「画被撕开」，和「眼前一白」不是一回事（开发纪要 56.6） |
