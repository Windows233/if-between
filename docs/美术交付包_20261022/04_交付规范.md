# 救C小游戏美术交付规范

## 文件与画布

- 交透明PNG和可编辑源文件。面板内部允许半透明深色，外部必须真透明，不用白底、黑底或棋盘格冒充透明。
- CSV中的尺寸是建议导出源尺寸，按游戏逻辑画布的四倍准备，方便统一缩放；程序与美术在今天同步时锁定。它们是新部件建议，不是对既有工程尺寸的断言。
- 同一个按钮或节点的不同状态必须同尺寸、同位置、同透明留白，切换不能跳动。
- 轨道、移动菱形、安全亮区必须分开交，不能合成一张图。安全窗口宽度由关卡参数控制，不把判定范围永久画进轨道。
- 所有文字、1/3进度和按键名称均由游戏排版。图片不包含中文、英文、数字或注释。
- 束缚线只含线与少量节点，不含角色、秋千和背景；线层与人物脚底锚点保持一致。
- 操场去C版保持1264×843，不重新生成整张地图。位置参照原图，不改变地砖透视、物件和入口。

## 交付目录

首版放在个人交付目录中，保留原素材。今天由程序确认后再接入正式资源目录，不直接覆盖现有图。建议名称见CSV。

每次提交附一张预览和一行说明：编号、状态、尺寸、版本、用于哪里。概念图中的发光与动作不要求首版全部实现。

## 自检

1. 在深色背景上能看清标记、亮区和进度节点。
2. 三个判定部件能独立移动、独立隐藏；轨道本身没有固定答案。
3. 预览缩小到游戏实际显示比例后仍可辨认，不只在大图上精致。
4. 透明边缘无白边；状态切换不跳位。
5. 人物不重复，黑线只缠C，不错误覆盖主角或UI文字。
6. 不把生成的整张示意图当最终游戏截图，不把示意图拆片冒充已完成的独立资产。

统一目标色仅作方向：深蓝黑底、银灰边框、浅青蓝稳定色、暗紫束缚色、柔和暗红失误色。最终以包内既有界面图和原场景为视觉基准。
