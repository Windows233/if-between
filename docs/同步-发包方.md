# 同步说明 · 发包方（给对面的 AI Agent 执行）

**规则：把仓库里的 `.git` 压缩成一个 zip 交回。不走网络，不算基点，不用 bundle。**

---

## 执行

### 1. 先确认工作区干净（不干净就先提交）

```bash
git status --short
```

必须为空。不为空就：

```bash
git add -A
git commit -m "<说清这次改了什么>"
```

**未提交的改动不在 `.git` 里** —— 直接打包等于没发。

### 2. 把 `.git` 压成 zip

- 取仓库根目录下的 **`.git`** 目录（隐藏目录），整个压成一个 zip，命名 `handoff-git.zip`，
  放在**仓库外面**（比如上一级目录）。
- 打包前确认 git 空闲：没有正在跑的 `fetch` / `merge` / `rebase` / `commit`。
- 体积大约几百 MB，压缩后变化不大（git 对象本身已压缩）。

### 3. 交回

把 `handoff-git.zip` 发回即可（QQ / 网盘都行）。

---

## 硬性要求

1. **先 commit**，再打包。
2. **打包时 git 必须空闲**，否则会拷到半截状态。
3. **只读仓库**：这个任务不改仓库里的任何文件，产出物放在仓库外面。
4. **不要为了瘦身**删素材、改 `.gitignore`、改写历史 —— 那会让对方合并出问题。
5. **不要用 `git bundle`、不要算基点**（那套更麻烦，弃用）。

---

## 对方会怎么用（仅供参考，你不用执行）

对方在自己的仓库里跑：

```bash
python tools/sync_from_package.py "<handoff-git.zip 的路径>"
```

脚本会：解开 zip → 把分支拉进 `pkg/<分支名>` → 跑数据自查 → 报告多了哪些提交、
动了哪些 `data/` 文件 → 确认后再合并。工具在两边的 `tools/` 里都有同一份。
