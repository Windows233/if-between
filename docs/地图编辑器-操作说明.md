## 一、打开

1. 用 Godot 打开这个项目（版本 4.7.2）。
2. 插件已经在 `project.godot` 里启用。打开后点击编辑器顶部的 **「IF 场景」** 主界面标签。
3. 没看到标签：到 `项目 → 项目设置 → 插件` 确认 `IF 地图编辑器` 已启用。

编辑器会载入地图列表里的第一张图。旧地图字段继续兼容；本批新增工具位于同一主界面，剧情节点编辑、演出指令编辑和时间轴暂缓。

**星星（`保存到 JSON *`）= 有没保存的改动。**

默认只显示两行常用操作。四个带 ▾ 的按钮每次只展开一组：地图管理含重新载入、丢弃草稿、备份历史与复制布局；显示设置含各层开关；选择与尺寸含坐标、尺寸和删除；排布与模板含复制、编组和模板。窄窗口会自动换行。

**找本批新功能**：左栏切到「工具」，点「场景检查 / 触发 / 试走设置…」，再选相应页签。视觉部件、翻转/旋转/缩放和模板更新在右侧物件属性卡内，先选中物件才能看到。

**新建地图**：点「新建地图…」，先选择完整 PNG 场景大图，核对缩略图和原始宽高，再填写唯一英文小写 `map_id` 与显示名。确认会创建 `art/map/` 背景和 `data/maps/` JSON，地图尺寸默认等于背景原图像素，中心生成 `start` 出生点。重名地图禁止覆盖，素材重名自动避让；取消不写文件。当前地图未保存的改动会先存草稿。新图尚未接入剧情或传送，请接着编辑入口与布局。

覆盖已有地图时会先把旧 JSON 快照存入 `user://map_editor_backups/<地图 ID>/`，每张图保留最近 20 份；无法备份时会取消覆盖。点「备份历史…」可把快照载入编辑器，检查后仍需手动保存才会改地图文件。

场景物件、地图画布和属性检查器之间的分隔线可以拖动；默认把更多宽度留给画布。画布会随面板尺寸自动适配地图，手动缩放或平移后保留当前视角；点「适应画布」可重新缩放并居中整张地图。

画布上每种颜色的意思：

| 颜色 | 是什么 |
| --- | --- |
| 红色方块 | 实体墙（`walls`，走不过去的地方） |
| 青色方块 | 传送区（`portals`，走上去按交互触发） |
| 绿色方块 | 物件（`actors`，家具、NPC） |
| 红色细框 | 选中物件的局部碰撞形状 |
| 蓝色半透明框 | 选中物件的交互范围 |
| 黄虚线 | 自动遮挡基线：有局部碰撞时取指定碰撞箱上边缘；旧物件仍取贴图框底边 |
| 橙虚线 | 手动遮挡基线（旧 `cover_y` 或新的排序偏移） |
| 紫点 + 名字 | 出生点（**可选中、可拖、可改坐标**） |
| 紫色区域框 + ID | 地图事件触发矩形；在「事件触发区域」列表选中后以白框定位 |
| 绿色网格 | 可走格（`WalkGrid` 算的，和真机一致） |
| 淡色细网格 | 摆放吸附参考，由左栏「工具」开关；与可走格分开控制 |
| 橙色虚线框 | **前景层**的实际范围，标注「恒在角色之上」（它不是物件，见第四节第 8 项） |
| 白框 + 八个白点 | 当前选中项；白点是改尺寸的手柄 |

**吸附精度**：左栏「工具」可设置「吸附步长」，默认 1 地图单位；「显示吸附网格」只控制网格是否可见，关闭后仍按当前步长吸附。网格用于摆放，不表示能否行走。精调可放大画布或填写位置/尺寸数值；已有地图的单位与背景像素比例不同，不能统一按一单位等于 12 像素计算。

表中按键为默认配置。重绑入口见第四节「试走设置、两图比较与快捷键」；操作时让画布获得焦点，避免在文本框输入过程中触发画布命令。

## 四、几件常做的事

### 1. 物件实例：局部碰撞、交互、复制与模板

物件选中后，检查器里的**物件局部属性**与地图位置分开编辑；碰撞和交互区都以物件贴图左上角为原点，移动、复制时会随实例一起移动。

- **启用局部几何**：选中旧物件后，点「启用物件独立碰撞与交互」。它会把已有 `reach` 转成局部交互区，并建立初始碰撞形状；不会删除地图级 `walls`，请检查是否重复阻挡。
- **把已有地图墙归入物件**：选中一件未隐藏、未锁定且未编组的物件，在属性栏点「归入地图墙…」。助手列出地图墙的索引与世界矩形，默认不勾选；由编辑师确认归属，再逐项勾选。重叠提示只作辅助，不代表这段墙属于该物件。
- **核对并确认归入**：检查差异预览中的移墙数量、局部碰撞坐标与排序基线。默认「保持当前遮挡基线」会把旧绝对基线换成实例偏移；当前画面不跳变，之后移动或复制时基线随物件走。取消勾选会清除旧基线覆盖，改用参考碰撞箱上边缘。确认后只改未保存布局，原墙删除、等效局部碰撞保留，世界交互范围不变，可一整步撤销/重做；最后仍需按「保存到 JSON」。人物、固定前景与带条件的物件不支持此入口。
- **画与调整碰撞箱**：先单选物件，切「画物件碰撞」，在空白处拖出新矩形。「选择」和「画物件碰撞」工具都可点中已有红框，拖内部移动，拖八个手柄缩放；选中物件的碰撞框优先于贴图框，即使碰撞伸出贴图也能操作。松手提交一整步，可撤销；Esc 取消拖动。多选、编组、隐藏或锁定时不编辑局部碰撞，形状删除仍用检查器。地图级墙继续用「画墙」。
- **改交互区**：在检查器编辑「交互区」的局部 `x / y / 宽 / 高`。它不要求与碰撞箱重合，因此书桌可用较窄碰撞、较宽的可达范围。
- **自动排序**：指定一个局部碰撞形状作为排序参考，自动基线取其上边缘。顶部「遮挡基线 Y」可直接微调；拖「拉遮挡基线」也可以手调。点「恢复自动」清除手动值。
- **多选复制**：在左侧场景树用 `Ctrl` / `Shift` 多选，或在画布上按住 `Shift` 逐个选中。复制和粘贴会保留实例属性、生成新 ID，并以 12 个游戏单位递增偏移；`Ctrl+D` 可快速复制。
- **编组与解组**：选中至少两件物件后点「编组」。场景树支持组内嵌组；选中组内成员时按所属最外层组扩展为整体选择、移动和复制，右侧显示当前主选物件。完整复制组会重建新物件 ID、组 ID 和父子关系。点「解组」移除所选物件涉及的分组，物件仍保留。
- **层级拖放与排序**：把物件或组拖到另一组的行内可设为子项；拖到行间可调同级顺序。要移到根级，拖到根级条目的前后位置。不能把组放进自身或后代，包含锁定物件时会拦截。层级写入 `editor_groups` 的 `parent`，树顺序写入 `editor_tree_order`；它们只组织编辑列表，不改变游戏的 Y 排序。
- **组名与折叠**：双击组名可改名，不能为空或与其他组重名；包含锁定成员时先解锁。改名保留组 ID 与成员，支持撤销/重做。同一地图刷新时保留折叠状态，切换地图不会套用上一张图的折叠状态。
- **定位物件**：点击树下方的「定位所选」，或让画布获得焦点后按 `F`；双击物件行也会定位。画布会缩放并居中可见选区，多选时包含所有可见成员。隐藏物件需先显示，锁定物件可以定位；定位只改变视角，不修改地图或撤销历史。
- **批量排布**：打开「对齐 / 分布」。对齐需至少选中两件；水平或垂直等间距需至少三件。等间距按物件矩形边缘计算并保留首尾位置；每次排布可整体撤销或重做。
- **保存模板**：选中单个物件，点「存为物件模板…」。新实例可从模板下拉框放置。此入口新建属性快照，重名不会覆盖；继承、源模板更新和已有实例更新在属性卡中操作，见后文。损坏或格式不合法的模板不进入可放置列表；失败不会留下半件物件。
- **试走**：点「当前布局试走」，用方向键或 WASD 移动，按空格检查当前交互目标。它使用未保存布局，但不会执行剧情。窗口内可勾选「显示碰撞/交互区」核对青色碰撞与黄色交互框，默认关闭以便观察实际遮挡。

局部碰撞/交互是可选字段，未转换的旧地图仍按旧逻辑运行。归入工具不会拆分背景图或整图前景层，移动前须确认美术是否可独立摆放；跨多个物件的共用墙仍保留在地图层。嵌套层级、模板更新和多部件入口已完成本批整合，正式地图迁移仍需逐图审核。室内外试点清单见 `地图编辑器-试点验收.md`。

- **素材浏览与放置**：左栏切到「素材」，按文件名筛选 `art/props/` 中的 PNG，将缩略图拖到地图显示区域即可创建并选中物件。物件源图的一个像素对应背景源图的一个像素，再换算成地图单位：`物件宽高 × 地图宽高 ÷ 背景原图宽高`，两个方向分别计算。拖动中的预览使用这一尺寸乘以画布缩放，鼠标始终对准物件中心，松手后尺寸一致。例：背景为 `5608×4488`、地图为 `467×374` 时，物件宽 `600` 源图像素约占 `49.96` 地图单位。素材列表直接扫描目录中的 PNG；尚未完成 Godot 导入的项目会标记「等待导入」，点击或拖动会请求重新扫描，仍失败时检查编辑器 Import/Output 错误。没有可读背景或地图尺寸无效时拒绝拖放，不回退到屏幕像素尺寸。非「选择」工具或落点在地图外时不接受素材放置。
- **新建物件后设置贴图**：点「新建物件」，在检查器选择项目贴图、输入有效路径后按 Enter，或点「导入贴图…」选外部 PNG；默认保留物件当前的位置、宽高和局部几何，贴图直接适配当前框，不再被大图撑大。只有显式点击「恢复原图尺寸」才按背景像素比例换算宽高。
- **PNG 导入等待**：文件复制完成后，编辑器会等待目标纹理真正可载入，并在需要时自动重试导入。若提示「已复制、纹理尚未就绪」，物件尚未创建；稍后刷新「素材」列表，使用已有图片即可，不要重复导入生成多份副本。真正无法导入时再检查 Godot Import/Output 错误。
- **按地图框选范围定大小**：选中一件物件，点检查器里的「框选贴图范围」，在地图上按住左键拖出目标框，松手后物件的位置与宽高就采用这个框，局部碰撞、交互区、视觉部件和遮挡基线同步缩放；支持反向拖动和撤销/重做，超出地图的边缘会截到地图内。框选时 Esc、切工具或切换选中项都会取消未完成的操作；隐藏、锁定、多选或编组物件不能单独框选。顶部「导入物件…」完成后自动进入此工具，可直接拖框；已有物件可先框好位置再导入贴图，也可导入后重新框选。

#### 隐藏与锁定

在左侧「场景」树选中物件或编组，用树下方的「隐藏所选」「锁定所选」切换状态。支持多选，编组物件会整体选中；树中用 `[隐藏]`、`[锁定]` 标记状态，按钮会随选区切换为显示或解锁。「全部显示」恢复当前地图的所有隐藏物件。窄侧栏中按钮自动换行。

- **隐藏**：不绘制该独立物件，也不能从画布拾取、拖动或画碰撞；仍可从列表选中并显示。游戏中的物件、碰撞与交互继续存在，保存地图也会保留它。已经画进大背景板的家具属于背景图片，隐藏物件不会擦掉那部分背景。
- **锁定**：物件继续显示，画布点击会穿过它，便于选中下面的物件；从列表选中后，位置/尺寸、遮挡基线和检查器只读，删除、对齐/分布、编组/解组也会被拦截。选区含锁定成员时整体变换被阻止。复制、存为模板仍可使用，新复制/放置实例默认显示且未锁定。
- **本机保存**：状态按地图 ID 与物件 ID 写入 `user://if_map_editor_scene_state.cfg`，重载地图或重开编辑器后恢复；不写入地图 JSON，不增加地图的未保存星号，也不随 Git 发给同事。它不参与地图撤销/重做；删除物件或撤销 ID 改名导致目标消失时，会清理对应状态。撤销删除后恢复的物件也默认显示且未锁定。
- **ID 与失败提示**：隐藏或锁定时物件 ID 只读，先显示并解锁再改名；ID 为空或重复时不能设置状态。配置文件损坏或不能写入时，底部会提示「状态已临时应用」，不会覆盖损坏文件；本次界面状态仍有效，持久保存需先处理文件问题。

#### 视觉部件与变换

选中物件，在右侧属性卡找到「视觉部件与变换」。上方提供「水平翻转」「垂直翻转」「顺时针 90°」「逆时针 90°」；填写缩放倍数后点「等比缩放」。多选时逐件以自身矩形中心变换，局部碰撞、交互区和部件矩形同步调整。用八个手柄改物件尺寸也会同步局部几何。

点「添加视觉部件」，为每个部件填写唯一 ID、`res://` 贴图路径和局部 `x / y / 宽 / 高`；ID、贴图路径按 Enter 应用。部件坐标以物件左上角为原点，可用「删除部件」移除。

| 层选择 | 保存值 | 用法 |
| --- | --- | --- |
| 固定后层 | `back` | 始终放在角色后方的部分 |
| 按基线遮挡 | `auto` | 按物件有效基线加该部件「遮挡基线偏移」判断前后 |
| 固定前层 | `front` | 始终盖在角色前方的部分 |

例如拱门的后侧与前缘可拆成后层和前层，中间主体设自动层。所有部件共用一个物件 ID、碰撞和互动内容，不会各自成为可交互物件。无多部件数据的旧物件继续使用原贴图；有部件列表时按列表绘制，不再额外叠加旧主贴图。`main` 已支持部件解析、分层和贴图变换，真实 MapView 回归核对了四向旋转、翻转与遮挡；遮挡多边形和图片切割工具不在本批范围。

#### 模板继承、更新与恢复默认

在「排布与模板」存为模板，再从模板下拉框放置实例。也可切左侧「模板」页，按名称、分类或标签筛选，拖到画布指定位置；双击则放到地图中央附近。拖入保留模板跟踪、碰撞和交互，预览按画布缩放显示。右侧属性卡会显示模板来源、格式版本、实例版本、当前模板版本，以及各字段的「默认 / 已覆盖 / 保留覆盖 / 未知」状态；鼠标提示可查看当前值和模板默认值。

**更新源模板**：选中来自模板的物件，按需要调整它的属性，在卡片内选「父模板（单继承）」、填写分类和逗号分隔的标签。点「预览：用当前属性更新源模板」，核对默认属性、父级关系和受影响子模板的差异，再点「确认更新源模板（不修改实例）」。重名的「存为模板」不能用来覆盖源模板。缺失父模板、继承循环、非法数据和过期预览会阻止更新。

模板文件中的 `version` 是格式版本，`template_version` 是内容修订号；单父继承保存为 `extends`。实例保存来源版本与默认快照 `source_template_defaults`，用于辨认哪些值由实例单独改过。源模板确认后立即写入模板资产；地图撤销不能撤销模板文件更新，已经放置的实例仍保留原样。

**把新默认更新到实例**：

1. 在场景树选中当前图内要更新的实例；单选或多选均可。
2. 点「预览更新所选实例」，核对将更新的字段与保留的实例覆盖。
3. 点「确认应用此预览」。更新比较旧默认、实例现值和新默认：跟随默认的字段接收新值，实例自行修改或删除的字段继续保留。
4. 检查布局后保存地图。实例更新可整步撤销；其他地图的实例需分别载入再更新。

**恢复默认**：勾选字段后点「预览恢复勾选字段」，或点「预览恢复全部模板默认」，再确认应用。恢复会明确替换主选实例的对应覆盖；多选的批量入口是「更新所选实例」，恢复默认仍针对主选实例。旧实例缺少可信快照时，先「建立安全基线（保留现状）」并确认，再按需要恢复字段。预览后若实例、选择或模板已变化，重新预览再确认。

#### 校验、定位与显式批量旧墙迁移

进入左栏「工具 → 场景检查 / 触发 / 试走设置… → 校验与迁移」。

**一键校验**：检查当前未保存布局的 ID、贴图/事件/模板引用、几何参数、排序参考、出生点阻挡，以及可走格连通区域和出生点到出口的可达性。点击当前图中带具体对象的错误/警告，可在画布定位；地图级连通警告需结合可走格找断路。导航校验复用 `WalkGrid`，超大地图可能跳过并提示警告；条件状态的差异需另用 flags 试走。

迁移预览只生成差异，不触发保存；只有「审阅后保存当前地图」才向主界面发出保存请求。保存会重新校验，警告须在确认窗口中明确接受；预览过期或确认期间地图变化时会拒绝写盘。正式地图的墙归属仍由地图编辑师审核。

1. 在物件下拉选择归属目标，逐项勾选要归入它的地图墙，核对原墙索引和世界矩形。默认不替你猜归属。
2. 按需要保留「保持当前遮挡基线」，点「加入 / 更新此物件」；对其他物件重复操作，组成当前地图的计划。
3. 检查计划表的「参与迁移」和墙归属；可移除所选计划。每段墙只能分配给一个物件，跨多个物件的建筑墙留在地图层。
4. 点「预览整批迁移」，核对每件物件前后的墙、局部碰撞、世界交互区与遮挡基线；任何目标预检失败，整批不应用。
5. 确认后点「应用到当前地图（可撤销）」。迁移数据层只改当前布局，可整步撤销；完成审阅后再用保存入口落盘。计划或地图改变后须重新预览。

旧的单物件「归入地图墙…」仍保留。人物、固定前景、带条件物件等归属限制沿用迁移器规则；旧地图墙不会因物件启用局部碰撞而自动删除。

**跨地图审阅与报告**：点「跨地图报告」，多选已有地图后点「生成所选地图报告」，或用「选择 manifest 文件…」读取已有迁移清单。检查逐图摘要，再用「导出报告…」保存 `.json` 结构化报告或 `.txt` 可读报告。报告导出不能覆盖 `data/` 中的游戏数据；可另选 `reports/` 等目录。跨图审阅读取磁盘地图，不会把当前草稿批量写回；它也不会跨图一键执行迁移。跨图问题先按地图 ID 切到对应图重新校验，再定位具体对象。

#### 试走设置、两图比较与快捷键

进入「场景工具」的「试走状态与地图比较」页：

1. 选「试走出生点」，按需勾「显示碰撞与交互区」。
2. 勾选状态变量名后设置布尔、数字或文本值；取消勾选表示该变量不存在，和布尔值 `false` 的含义不同。列表会收集已有条件变量，也能用「添加状态」补充名字。
3. 点「用当前未保存布局试走」。这份 flags 只用于预览，不修改地图、正式存档或剧情变量；出生点被当前碰撞挡住时会提示，位置不会被悄悄挪开。

顶部「当前布局试走」继续使用默认设置；需要指定 flags 和出生点时使用工具窗口入口。方向键/WASD 移动、空格检查物件或传送区目标，均不执行剧情或传送。区域事件与 once 的实际触发需在游戏中验证。

**两图比较**：在「只读比较地图（含昼夜版本）」中选另一张图和比较侧出生点，点「与当前布局并列比较（只读）」。左侧使用当前未保存布局；不同地图的右侧读取磁盘 JSON，同图比较则使用当前布局副本。两侧共用所设 flags，可分别选出生点，并排观察条件显示、碰撞/交互与外观；两侧均只读，不移动或执行剧情，不提供像素 diff、自动合并、提取遮挡物或写回。

**可配快捷键**：切「快捷键」页，点某动作的按键按钮后直接按组合键；`Esc` 取消捕获。支持撤销、重做、复制、粘贴、复制并偏移、删除、定位所选和取消操作，重复组合键会显示冲突；可点「恢复全部默认快捷键」。配置保存在本机 `user://if_map_editor_shortcuts.cfg`，不写地图，不改游戏键位。

#### 矩形事件触发区域

进入「场景工具 → 事件触发区域」，点「添加区域」，填写唯一 ID 并从列表绑定已有事件。列表来自 `data/events/` 中已有 JSON 的文件名，不创建新事件或剧情节点。

- **范围**：填写 `X / Y / 宽 / 高`，宽高必须为正；点可用 `1 × 1` 矩形表示。也可先在主画布选中矩形物件、墙或传送区，再点「从当前选区取矩形」。在触发区域列表选中项目会让画布定位并高亮。
- **开关**：「启用」控制该区域是否生效；「本存档只触发一次」保存为 `once`。运行器把一次性标记按地图 ID 与触发器 ID 写入世界状态，随存档保存；离图重进不会清除，新游戏随世界状态重置。已用于正式存档的触发器 ID 不宜随意改名，以免被当成新的触发器；存读档实际表现仍需整合验证。
- **条件**：「条件参数」使用现有 `Condition JSON`，例如 `{"var":"flag/name","op":"==","value":true}`；支持 `exists / all / any / not`。填写后点「应用条件」；留空再应用会移除条件，非法输入不会改地图。

| 方式 | 保存值 | 请求事件的时机 |
| --- | --- | --- |
| 进入地图 | `enter_map` | 进入地图后检查 |
| 进入区域 | `enter` | 玩家进入矩形区域 |
| 区域内按交互键 | `interact` | 玩家在区域内按交互键 |
| 点击区域 | `click` | 点击该矩形区域 |

配置写入地图 `triggers`，支持地图保存与撤销/重做；「删除区域」移除当前项。`main` 运行时已接入四种方式、条件和 once 世界状态记录：事件启动未被接受时不会消耗一次性标记；忙碌或暂停时不派发。交互方式优先处理有效传送区，再检查区域触发与附近物件，避免把触发区域叠在要使用的传送口上。

插件与游戏的完整触发/存读档链路仍待整合验证。编辑器当前试走不执行事件，不能用空格检查目标代替触发验收。多边形区域、剧情正文、分支节点图、演出指令与时间轴均不在此入口编辑。

### 2. 画 / 改碰撞箱

- **画新的**：点「画墙」→ 在图上按住左键拉一个框 → 松手就进 `walls`。
  刚画完会直接选中它。
- **改已有的**：切回「选择」→ 点中一个红块 → 拖着走；或用八个白点拉边角。
- **抠数字**：选中之后在上面的 `x / y / 宽 / 高` 里敲，画面立刻跟着动
  （「差 4 像素」这种话，现在直接敲 4）。
- **删掉**：选中之后点右边那个 **「删除选中」**（`Delete` 键同样管用）。
  删错了别慌：**没保存之前点「重新载入」就能全部撤回来**。

### 3. 画 / 改传送区

跟画墙一样，只是工具换成「画传送区」。新画的会自带：

```json
{ "rect": [...], "label": "新传送区", "locked": true, "blocked_text": "（还没有连接）" }
```

`locked: true` 的意思是**摆在这儿但还不通往任何地方**（走上去弹那句话）。
要真接上，去 `portals` 里补 `to` + `spawn`（或者 `event` 挂一段剧情），
再把 `locked` / `blocked_text` 去掉。

### 4. 把一张图的布置复制到另一张（白天版 ↔ 夜间版）

点顶部 **「复制布局到…」** → 选目标地图 →「覆盖过去」。

- 复制的是**碰撞箱、传送区、物件**这三样，在目标图里**整个换掉**。
- 编组关系一并复制；当前入口不复制 `triggers`，触发区域请在目标图单独配置。
- **尺寸、背景、前景层、音乐、脚步都不动** —— 那些是每张图自己的。
- 出生点默认不动；要一起复制就勾上「连出生点一起复制」。
- 覆盖是**立刻写盘**的（不用再点保存）。做完看一眼状态栏那句话。

> 用在「同布置、不同配色」的图上：白天版摆一遍，覆盖到夜间版。
> **反过来也成立** —— 夜间版摆好的，也能覆盖回白天版。

### 5. 拉遮挡基线（就是那个「挡不挡人」的分界线）

1. 选中一件物件，在右侧物件属性卡点「拉遮挡基线」。
2. 在画布上拖动该物件的**黄/橙线**（只有写了 `cover: true` 的物件才有）。
3. **上下拖**，线跟着走；松手就写进那份 JSON 的 `cover_y`。
4. 拖完之后线变**橙色**（= 手动覆盖）。新局部碰撞物件会记录相对自动基线的偏移；旧物件保留绝对 `cover_y`。想回到自动，点「恢复自动」。

局部碰撞物件默认用碰撞框上边缘自动排序，可在属性卡选择参考碰撞框、设置偏移、修改有效基线或恢复自动。碰撞的 x/y/宽/高和交互区域也保留数值入口；画布拖动是另一种调整方式。

> ⚠️ 写了 `cover_y` 之后，那件物件的 `rect` 底边**就不再管遮挡**了。
> 只在该手调的那几件上写，别养成每件都写的习惯。

### 6. 出生点（玩家进这张图时落在哪儿）

- **改位置**：切「选择」→ 点那颗紫点 → 拖着走；或在 x/y 里敲数字。
  （出生点没有「宽高」，那两个框对它自动禁用。）
- **加一个**：点「加出生点」→ 起个名字 → 它先落在**地图正中** → 再拖到位置。
- **删一个**：选中 → 「删除选中」。**有跨文件关联的会先弹确认**，把挂着的东西列出来
  （见下面「删除与关联检查」）。

**命名规矩**：出生点是按名字被引用的 —— 传送点写 `"spawn": "<名字>"`，
新游戏固定找 `start`。所以：

- 名字**别重复**（重了编辑器不给加）；
- **至少留一个 `start`**，不然新游戏和一部分传送点会指空；
- 习惯命名：从哪儿来的叫 `from_<来源>`（`from_overworld`、`from_desk_shop`）。

> ⚠️ **出生点只管「落在哪儿」，不管「朝哪儿」。** 数据里 `spawns` 只有坐标，
> `enter_map()` 也只设位置 —— **没有任何一处按它设朝向**。玩家进图时的朝向是
> 「上一张地图带过来的朝向」，新开局则是默认朝向。
> 想固定朝向（比如进门朝上），得在**剧情**里用 `place_player`，或者在那段入场的
> 代码里写一行 `player.facing = Vector2.UP`（门卫室那张图的调试分支就是这么干的）。
> 如果以后要「每张图/每个出生点自带朝向」，得往数据里加字段（现在没有）。


### 7. 物件（家具与 NPC）：加一件、改名字、编互动内容

选中一件物件，面板下面会多出一块 **「物件属性」**。

**加一件**：点「加物件」→ 它先落在地图正中（40×40 的绿框）→ 拖到位置 → 再填下面的信息。
**「加物件」旁边那条「导入图像…」**：从电脑上挑一张 PNG → 它会被拷进 `art/props/`
（名字自动收拾成小写下划线，重名加 `_2`）→ **新建一件默认勾上「会挡人」的遮挡物件** →
导入完成后直接在地图上拖框设置位置和大小，再按需拉它的黄基线。**从美术给的图里挑一块做遮挡片，走这条路。**

**能改的：**

| 字段 | 说明 |
| --- | --- |
| `id` | 内部标识，一件图里别重名 |
| 名字 | 显示名；没贴图时就画这个名字 |
| 贴图 | 直接写 `res://art/props/xxx.png`，或用右边的下拉从 `art/props/` 里挑 |
| ☐ 只装饰 | 勾上 = 只画、**不参与交互**（玩家走过它不会弹出交谈） |
| ☐ 会挡人 | 勾上 = 按站位分前后（人在它北边被它盖住） |
| ☐ 永远画在角色之上 | 给前景小物件用（一直盖着人，不按站位） |

**互动内容**面板会显示这件物件当前用**哪种写法**：

| 写法 | 面板上怎么编 |
| --- | --- |
| 单句旁白（`line`） | 一个输入框，写完事 |
| 多句对话（`talk`） | **一行一句**：说话人 / 左或右 / 立绘（下拉，含主角表情）/ 正文，行尾有 `↑` `↓` `✕`，底下「加一句」 |
| 挂剧情事件（`event`） | 属性卡下拉框可绑定/取消已有事件；正文仍在 `data/events/<id>.json` 中，不编辑剧情正文 |
| 多动作菜单（`actions`） | 只读（暂不编辑） |

右边两个按钮可以在「单句旁白 / 多句对话」之间**换写法**（原内容会搬过去）。
挂了剧情事件的物件先在事件下拉框选择空绑定，再切回单句或多句；原有对白字段会保留。给装饰物件绑定事件会同步取消「只装饰」，并支持整步撤销，避免产生无效入口。多动作菜单沿用原结构，暂不提供顶层事件替换。

> **说话人留空 = 旁白**；主角说话就填 `我`，侧别选**右**，立绘挑 `protagonist/…`
> （哪张表情用在哪，看美工那份《表情使用方法.txt》）。
>
> **编辑器不会把不认得的字段抹掉** —— 比如对话行里的 `size_delta`（字号增减）、
> `shake`（抖动）它不显示，但保存时原样留着。你要写这类效果，还是得手改 JSON。

### 7.5 删除与关联检查（防手滑）

删东西之前，编辑器会查**跨文件的关联**，有就列出来让你确认：

| 删什么 | 会提醒什么 |
| --- | --- |
| 物件 | 挂着剧情事件「ch1_sleep」／动作「睡下」挂着事件／有出现条件（if）／演完会写状态（item/key） |
| 传送点 | 连着地图「overworld」／挂着剧情事件／动作是 overworld／现在是锁着的 |

**为什么要拦**：这类错误**数据完全合法，`check_data` 查不出来** —— 它只查「引用的东西存不存在」，
查不出「这里本来该有个人来触发」。删掉之后正文文件还在，只是**再也没有入口**了。

同样地，给一件挂着剧情的物件勾上「**只装饰**」时也会先问一句（勾上它就不参与交互，
剧情同样触发不到）—— 这条是伪装成显示选项的陷阱，所以单独拦。

### 8. 前景层（那道「挡人的下围墙」，可以直接点它）

前景层是 `overlay`：一整张图，**恒在角色之上**，**整张拉伸到地图大小**。

**选中它**：切「选择」→ 点那块橙色虚线框里的地方。
它常常压在墙上、门洞上，别的层会先被点中 —— 想干净地点它，就把「墙 / 物件」
那两个勾**先取消**（显示开关同时管能不能点中）。选中之后面板上会出现：

| 控件 | 作用 |
| --- | --- |
| 图片 | 直接的路径输入框，敲完立刻换 |
| **导入图像…** | 挑一张 PNG 拷进 `art/map/`，按习惯命名 `<地图名>_wall`，并设为前景层 |
| 清除 | 把前景层去掉（数据里那条没了，图还留在 `art/map/` 里） |

**图的尺寸不用管** —— 游戏里它会被拉伸到整张地图（`map_view._add_overlay`）。
所以美术给的图多大都行。

**它没有位置和尺寸可调**：数据里前景层只有一条路径。那四个数字框对它自动禁用，
拖也拖不动。要改「挡住哪儿」，改的是**图本身**（画的时候就在图里定好了）。

**看它盖住了什么**：显示行最右那个「前景层」滑条拉淡。

**下围墙两种做法的分工**：

| 做法 | 数据长什么样 | 哪些图 | 编辑器的表现 |
| --- | --- | --- | --- |
| 前景层 | `overlay` 一个路径 | 卧室、委托屋、门卫室 | 铺一张图 + 橙色虚线框，**能选中、能换图** |
| 遮挡物件 | 一个 `cover: true` 的 actor | 集市（`bottom_wall`）、门卫室的桌子 | 绿框 + **可拖的黄基线** |

> 什么时候用哪种：人**只会**在它前面走 → 前景层（恒盖，最省事）；
> 人**既会在前面也会在后面**（门洞过道那种，人在前面时不能被墙压住）→
> 遮挡物件，按基线切换。

## 五、可走格（验「人到底能不能站这儿 / 走得过去」）

勾上「可走格」→ 面板底下会铺一层网格：

- **绿色格** = 人站得住（基础脚底方块 16×16，随地图人物比例缩放）
- **红色格** = 站不住

**修改墙、物件碰撞或物件位置后自动刷新可走格**；连续修改会合并计算，旧网格先清除，避免显示过期布局。
也可点「重算可走格」立即刷新。关闭显示期间不计算，下次打开按最新布局生成；撤销、重做和切图同样会更新。
大图计算可能需要一两秒，因为它把整张图逐格交给游戏同一份 `WalkGrid.is_free` 判定。

**可走格不与碰撞框边缘重合是正常的**：碰撞框表示障碍物本身，网格表示主角的脚底落点。
脚底框只要与障碍相交，该落点就标红；基础比例下左右各留 8、脚底向上伸 16，具体随地图人物比例变化。
所以障碍外侧也可能标红，窄缝需要容得下整个脚底框。要精确核对，打开下面的「脚底框（跟鼠标）」。

这一层是拿来验这几件事的：

- 新画的墙有没有把路堵死；
- 两道家具之间那条缝，够不够 16 像素的脚钻过去（缺口问题就是这么找出来的）；
- 门口那块传送区，里面到底有没有一格站得住。

---

### 更细的一把尺：**脚底框（跟鼠标）**

勾上显示行最后那个 **「脚底框（跟鼠标）」**，鼠标停在图上就会画出**主角的碰撞箱**：
基础比例下是 **16×16 的方块，以鼠标那个点为底、往上伸**（脚下一线为 0），随地图人物比例缩放。颜色就是答案：

- **绿** = 站得住，**红** = 站不住（判据直接调游戏那份 `WalkGrid.is_free`，不另算）
- 框旁边还写着落点坐标，量位置时能直接读数

**它和「可走格」的分工**：可走格是**整张图**的粗看（一眼看哪儿能走），
脚底框是**一个点**的精量 —— 「这条缝够不够人钻过去」「门口往里那一格站不站得住」
用它最准。改完墙它会立刻跟着变。
## 六、显示开关的两个作用（容易踩）

那一排勾选框**不只是显示/隐藏**，它同时决定「这一类能不能被点中」：

- 物件压在碰撞块上是常事（委托屋的书桌、门卫室的桌子）。物件开着的时候，
  你怎么点都是选中物件，底下那块墙**永远点不到** —— 这时把「物件」取消勾选，
  再点就选中墙了。
- 反过来也一样：只想调物件、不想误碰墙，就把「墙」关掉。
- 把某一类关掉时，**挂在它上面的选中会一起收起来**（不然会出现看不见的白框
  还挂着八个手柄）。

## 七、保存与回滚

- 改完点「保存到 JSON」→ 先校验当前布局；有错误时阻止保存，有警告时弹出列表供明确确认，通过后写回 `data/maps/<地图>.json`。确认期间地图若又有变化，需要重新保存并校验。
- **格式是对着 git 友好做的**：整数写成整数（`96` 不是 `96.0`），
  键序不动，两空格缩进 —— 只有你改过的那几个数字会出现在 diff 里。
- 覆盖已有地图前，编辑器会把磁盘上的旧 JSON 原样快照到
  `user://map_editor_backups/<地图 ID>/`，每张图最多保留最近 20 份；快照失败时保存会取消，不会覆盖原文件。
- 回滚旧版：点「备份历史…」选择时间点载入编辑器，检查后再点「保存到 JSON」；快照载入本身不会写磁盘。已提交版本仍可从 git 历史查看。
- 「重新载入（丢弃改动）」= 从磁盘重读，丢掉这次没保存的改动。

**保存完，游戏里不会自动变** —— 游戏每次进地图都从 JSON 读，
所以下次进那张图（或重新跑一次）就是新的。

---

### 没保存就切地图 —— 不会丢（草稿）

切到另一张图的**那一刻**，编辑器会先把这张图的改动**自动存成草稿**，切回来接着改。
草稿放在 `user://map_editor_drafts/`（**在仓库外面**，不会跟着 git 走，
`check_data` 也看不见它）。

怎么看哪张图有草稿：**地图下拉里带 ` *` 的就是**（`gatehouse *`）。
选中它载入时，状态栏会写「载入的是 xxx 的草稿（2026-09-27 12:30:05 存下的，还没保存）」。

想舍弃草稿：**「丢弃草稿」按钮**（会问一句）。别的途径也会清掉草稿：

| 动作 | 草稿 |
| --- | --- |
| 点「保存到 JSON」 | **清掉**（已写进仓库；覆盖旧地图前另留自动快照） |
| 点「重新载入（丢弃改动）」 | **连草稿一起丢**（这个按钮的意思就是「不要这些改动」） |
| 点「丢弃草稿」 | 清掉 |
| 直接切去别的图 | 留着，回来还在 |

> 草稿只记「这张图的 JSON 内容」。它不会替你保存美术、也不会碰到 `data/events/`。

## 八、暂缓项与功能边界

| 想做的事 | 现在去哪儿做 |
| --- | --- |
| 出生点带朝向 | 数据里没有这个字段（朝向归剧情 `place_player` 管） |
| 编辑物件自身的台词 | 右侧「互动内容」保留单句旁白 / 多句对话编辑，见第四节第 7 项 |
| 从插画上切贴图、定物件的贴图框 | 还是 `tools/slice_props.py` 那套（编辑器只引用 `art/props/` 里已有的图） |
| 编剧情正文、节点分支、选项、演出指令或时间轴 | 本批明确暂缓；地图物件与触发区域引用现有 `data/events/*.json`，不编辑事件正文 |
| 改已有地图的整体尺度 | 新建地图已有顶部入口；已有地图整体重定尺度仍需单独规划 |
| 自动像素 diff / 提取遮挡物 | 本批已有两图并列只读比较；像素差分、切图与自动提取未做 |
| 多边形触发器 / 局部遮挡多边形 | 未做；当前触发区域用矩形，多段视觉用 back/auto/front 部件 |
| 跨地图一键迁移 / 自动猜墙归属 | 未提供；批量迁移按当前图的明确归属计划，跨图报告只读 |
| 编辑前景层的形状（画/擦它的像素） | 还没做 —— 那是改画，得动 PNG |

## 九、出问题了先看这两处

1. **面板一片空白**：先在「地图」下拉里选一张图 —— 打开时载入的是列表第一张，
   可能不是你想要的。
2. **画面卡一下**：勾「可走格」或点「重算可走格」时要算整张图，
   大图会顿一两秒，正常。
