## 一、打开

1. 用 Godot 打开这个项目（版本 4.7.2）。
2. 插件已经在 `project.godot` 里启用。打开后点击编辑器顶部的 **「IF 场景」** 主界面标签。
3. 没看到标签：到 `项目 → 项目设置 → 插件` 确认 `IF 地图编辑器` 已启用。

编辑器会载入地图列表里的第一张图。首批重制功能仍在原插件里，不是独立应用；旧地图字段继续兼容。

## 二、面板长什么样

```
地图：[gatehouse ▾]  [重新载入] [适应画布] [保存 *] [备份历史…] [复制布局到…]
工具：[选择] [画墙] [画传送区] [拉遮挡基线] [画物件碰撞]
场景物件：[可多选的物件列表]
列表操作：[隐藏所选 / 显示所选] [锁定所选 / 解锁所选] [全部显示]
操作：[撤销] [重做] [复制] [粘贴] [复制并偏移] [编组] [解组] [对齐 / 分布] [存为模板] [当前布局试走]
画布：[地图与选中对象]
检查器：[物件局部碰撞 / 交互区 / 排序] 或 [对象外观 / 互动内容]
```

**星星（`保存到 JSON *`）= 有没保存的改动。**

覆盖已有地图时会先把旧 JSON 快照存入 `user://map_editor_backups/<地图 ID>/`，每张图保留最近 20 份；无法备份时会取消覆盖。点「备份历史…」可把快照载入编辑器，检查后仍需手动保存才会改地图文件。

场景物件、地图画布和属性检查器之间的分隔线可以拖动；默认把更多宽度留给画布。画布会随面板尺寸自动适配地图，手动缩放或平移后保留当前视角；点「适应画布」可重新缩放并居中整张地图。

画布上每种颜色的意思：

| 颜色 | 是什么 |
| --- | --- |
| 红色方块 | 实体墙（`walls`，走不过去的地方） |
| 青色方块 | 传送区（`portals`，走上去按交互触发） |
| 绿色方块 | 物件（`actors`，家具、NPC） |
| 红色细框 | 选中物件的局部碰撞形状 |
| 蓝色半透明框 | 选中物件的交互范围 |
| 黄虚线 | 自动遮挡基线：有局部碰撞时取指定碰撞箱上边缘；旧物件仍取贴图框底边 |
| 橙虚线 | 手动遮挡基线（旧 `cover_y` 或新的排序偏移） |
| 紫点 + 名字 | 出生点（**可选中、可拖、可改坐标**） |
| 绿色网格 | 可走格（`WalkGrid` 算的，和真机一致） |
| 橙色虚线框 | **前景层**的实际范围，标注「恒在角色之上」（它不是物件，见第九节） |
| 白框 + 八个白点 | 当前选中项；白点是改尺寸的手柄 |

---

- 复制布局、删除确认、加出生点这些**弹窗**，内容放在**限高的滚动区**里 —— 条目再多，
  底下的「确定 / 取消」也永远在屏幕内（之前内容一长就会把按钮顶出屏幕，点不到）。
- 「选中项属性」那一块也一样在滚动区里，行数再多也不会把画布挤没。
- 选地图那个下拉不会被长名字撑宽。

## 四、几件常做的事

### 1. 物件实例：局部碰撞、交互、复制与模板

物件选中后，检查器里的**物件局部属性**与地图位置分开编辑；碰撞和交互区都以物件贴图左上角为原点，移动、复制时会随实例一起移动。

- **启用局部几何**：选中旧物件后，点「启用物件独立碰撞与交互」。它会把已有 `reach` 转成局部交互区，并建立初始碰撞形状；不会删除地图级 `walls`，请检查是否重复阻挡。
- **把已有地图墙归入物件**：选中一件未隐藏、未锁定且未编组的物件，在属性栏点「归入地图墙…」。助手列出地图墙的索引与世界矩形，默认不勾选；由编辑师确认归属，再逐项勾选。重叠提示只作辅助，不代表这段墙属于该物件。
- **核对并确认归入**：检查差异预览中的移墙数量、局部碰撞坐标与排序基线。默认「保持当前遮挡基线」会把旧绝对基线换成实例偏移；当前画面不跳变，之后移动或复制时基线随物件走。取消勾选会清除旧基线覆盖，改用参考碰撞箱上边缘。确认后只改未保存布局，原墙删除、等效局部碰撞保留，世界交互范围不变，可一整步撤销/重做；最后仍需按「保存到 JSON」。人物、固定前景与带条件的物件不支持此入口。
- **画碰撞箱**：先选物件，切「画物件碰撞」，再在画布上拖出矩形。用检查器数值框微调、添加或删除形状。地图级墙仍用「画墙」工具。
- **改交互区**：在检查器编辑「交互区」的局部 `x / y / 宽 / 高`。它不要求与碰撞箱重合，因此书桌可用较窄碰撞、较宽的可达范围。
- **自动排序**：指定一个局部碰撞形状作为排序参考，自动基线取其上边缘。顶部「遮挡基线 Y」可直接微调；拖「拉遮挡基线」也可以手调。点「恢复自动」清除手动值。
- **多选复制**：在左侧场景树用 `Ctrl` / `Shift` 多选，或在画布上按住 `Shift` 逐个选中。复制和粘贴会保留实例属性、生成新 ID，并以 12 个游戏单位递增偏移；`Ctrl+D` 可快速复制。
- **编组与解组**：选中至少两件物件后点「编组」；左侧场景树按「编组 → 物件」显示，未编组物件直接列在根部。选中组或其中一件即可整体选择、移动、复制，右侧仍显示当前主选物件；复制组会生成新的组关系。点「解组」只移除分组，不删除物件。分组写入地图根节点的编辑器专用 `editor_groups` 字段，运行时不会读取；复制布局时分组关系一并复制。
- **组名与折叠**：双击组名可改名，不能为空或与其他组重名；包含锁定成员时先解锁。改名保留组 ID 与成员，支持撤销/重做。同一地图刷新时保留折叠状态，切换地图不会套用上一张图的折叠状态；目前不支持嵌套分组或拖动层级排序。
- **定位物件**：点击树下方的「定位所选」，或让画布获得焦点后按 `F`；双击物件行也会定位。画布会缩放并居中可见选区，多选时包含所有可见成员。隐藏物件需先显示，锁定物件可以定位；定位只改变视角，不修改地图或撤销历史。
- **批量排布**：打开「对齐 / 分布」。对齐需至少选中两件；水平或垂直等间距需至少三件。等间距按物件矩形边缘计算并保留首尾位置；每次排布可整体撤销或重做。
- **保存模板**：选中单个物件，点「存为物件模板…」。新实例可从模板下拉框放置。模板是保存时的属性快照；之后编辑实例不会回写模板，也不会自动更新已放置实例。损坏或格式不合法的模板不会进入可放置列表；重名保存或写入失败会报错并保留已有文件，放置失败不会留下半件物件。
- **试走**：点「当前布局试走」，用方向键或 WASD 移动，按空格检查当前交互目标。它使用未保存布局，但不会执行剧情。

局部碰撞/交互是可选字段，未转换的旧地图仍按旧逻辑运行。归入工具不会拆分背景图或整图前景层，移动前须确认美术是否可独立摆放；跨多个物件的共用墙仍保留在地图层。正式地图尚未迁移；模板继承、嵌套层级、层级拖放和复杂多段遮挡仍未完成。只读盘点与室内外试点清单见 `地图编辑器-试点验收.md`。

- **素材浏览与放置**：左栏切到「素材」，可按文件名筛选 `art/props/` 中的 PNG；将缩略图拖到地图显示区域即可创建并选中一件物件。当前地图已有同贴图实例时沿用其尺寸；否则按贴图像素除以 12 换算为游戏单位，贴图会保持比例。之后可在画布拖动、改尺寸，并在右侧设置碰撞、遮挡与交互。切到非「选择」工具或拖到地图外时不接受素材放置。

#### 隐藏与锁定

在左侧「场景」树选中物件或编组，用树下方的「隐藏所选」「锁定所选」切换状态。支持多选，编组物件会整体选中；树中用 `[隐藏]`、`[锁定]` 标记状态，按钮会随选区切换为显示或解锁。「全部显示」恢复当前地图的所有隐藏物件。窄侧栏中按钮自动换行。

- **隐藏**：不绘制该独立物件，也不能从画布拾取、拖动或画碰撞；仍可从列表选中并显示。游戏中的物件、碰撞与交互继续存在，保存地图也会保留它。已经画进大背景板的家具属于背景图片，隐藏物件不会擦掉那部分背景。
- **锁定**：物件继续显示，画布点击会穿过它，便于选中下面的物件；从列表选中后，位置/尺寸、遮挡基线和检查器只读，删除、对齐/分布、编组/解组也会被拦截。选区含锁定成员时整体变换被阻止。复制、存为模板仍可使用，新复制/放置实例默认显示且未锁定。
- **本机保存**：状态按地图 ID 与物件 ID 写入 `user://if_map_editor_scene_state.cfg`，重载地图或重开编辑器后恢复；不写入地图 JSON，不增加地图的未保存星号，也不随 Git 发给同事。它不参与地图撤销/重做；删除物件或撤销 ID 改名导致目标消失时，会清理对应状态。撤销删除后恢复的物件也默认显示且未锁定。
- **ID 与失败提示**：隐藏或锁定时物件 ID 只读，先显示并解锁再改名；ID 为空或重复时不能设置状态。配置文件损坏或不能写入时，底部会提示「状态已临时应用」，不会覆盖损坏文件；本次界面状态仍有效，持久保存需先处理文件问题。

### 2. 画 / 改碰撞箱

- **画新的**：点「画墙」→ 在图上按住左键拉一个框 → 松手就进 `walls`。
  刚画完会直接选中它。
- **改已有的**：切回「选择」→ 点中一个红块 → 拖着走；或用八个白点拉边角。
- **抠数字**：选中之后在上面的 `x / y / 宽 / 高` 里敲，画面立刻跟着动
  （「差 4 像素」这种话，现在直接敲 4）。
- **删掉**：选中之后点右边那个 **「删除选中」**（`Delete` 键同样管用）。
  删错了别慌：**没保存之前点「重新载入」就能全部撤回来**。

### 3. 画 / 改传送区

跟画墙一样，只是工具换成「画传送区」。新画的会自带：

```json
{ "rect": [...], "label": "新传送区", "locked": true, "blocked_text": "（还没有连接）" }
```

`locked: true` 的意思是**摆在这儿但还不通往任何地方**（走上去弹那句话）。
要真接上，去 `portals` 里补 `to` + `spawn`（或者 `event` 挂一段剧情），
再把 `locked` / `blocked_text` 去掉。

### 4. 把一张图的布置复制到另一张（白天版 ↔ 夜间版）

点顶部 **「复制布局到…」** → 选目标地图 →「覆盖过去」。

- 复制的是**碰撞箱、传送区、物件**这三样，在目标图里**整个换掉**。
- **尺寸、背景、前景层、音乐、脚步都不动** —— 那些是每张图自己的。
- 出生点默认不动；要一起复制就勾上「连出生点一起复制」。
- 覆盖是**立刻写盘**的（不用再点保存）。做完看一眼状态栏那句话。

> 用在「同布置、不同配色」的图上：白天版摆一遍，覆盖到夜间版。
> **反过来也成立** —— 夜间版摆好的，也能覆盖回白天版。

### 5. 拉遮挡基线（就是那个「挡不挡人」的分界线）

1. 点「拉遮挡基线」。
2. 点一件**身上有黄/橙线**的物件（只有写了 `cover: true` 的物件才有）。
3. **上下拖**，线跟着走；松手就写进那份 JSON 的 `cover_y`。
4. 拖完之后线变**橙色**（= 手动覆盖）。新局部碰撞物件会记录相对自动基线的偏移；旧物件保留绝对 `cover_y`。想回到自动，点「恢复自动」。

什么时候需要手动拉：**贴图底下自带一圈阴影、或者切件时多切了几像素**，
「贴图框的下边界」就不是物件落在地上那条线了 —— 摊上这种情况才拉。

> ⚠️ 写了 `cover_y` 之后，那件物件的 `rect` 底边**就不再管遮挡**了。
> 只在该手调的那几件上写，别养成每件都写的习惯。

### 6. 出生点（玩家进这张图时落在哪儿）

- **改位置**：切「选择」→ 点那颗紫点 → 拖着走；或在 x/y 里敲数字。
  （出生点没有「宽高」，那两个框对它自动禁用。）
- **加一个**：点「加出生点」→ 起个名字 → 它先落在**地图正中** → 再拖到位置。
- **删一个**：选中 → 「删除选中」。**有跨文件关联的会先弹确认**，把挂着的东西列出来
  （见下面「删除与关联检查」）。

**命名规矩**：出生点是按名字被引用的 —— 传送点写 `"spawn": "<名字>"`，
新游戏固定找 `start`。所以：

- 名字**别重复**（重了编辑器不给加）；
- **至少留一个 `start`**，不然新游戏和一部分传送点会指空；
- 习惯命名：从哪儿来的叫 `from_<来源>`（`from_overworld`、`from_desk_shop`）。

> ⚠️ **出生点只管「落在哪儿」，不管「朝哪儿」。** 数据里 `spawns` 只有坐标，
> `enter_map()` 也只设位置 —— **没有任何一处按它设朝向**。玩家进图时的朝向是
> 「上一张地图带过来的朝向」，新开局则是默认朝向。
> 想固定朝向（比如进门朝上），得在**剧情**里用 `place_player`，或者在那段入场的
> 代码里写一行 `player.facing = Vector2.UP`（门卫室那张图的调试分支就是这么干的）。
> 如果以后要「每张图/每个出生点自带朝向」，得往数据里加字段（现在没有）。


### 7. 物件（家具与 NPC）：加一件、改名字、编互动内容

选中一件物件，面板下面会多出一块 **「物件属性」**。

**加一件**：点「加物件」→ 它先落在地图正中（40×40 的绿框）→ 拖到位置 → 再填下面的信息。
**「加物件」旁边那条「导入图像…」**：从电脑上挑一张 PNG → 它会被拷进 `art/props/`
（名字自动收拾成小写下划线，重名加 `_2`）→ **新建一件默认勾上「会挡人」的遮挡物件** →
你拖到位置、拉它的黄基线。**从美术给的图里挑一块做遮挡片，走这条路。**

**能改的：**

| 字段 | 说明 |
| --- | --- |
| `id` | 内部标识，一件图里别重名 |
| 名字 | 显示名；没贴图时就画这个名字 |
| 贴图 | 直接写 `res://art/props/xxx.png`，或用右边的下拉从 `art/props/` 里挑 |
| ☐ 只装饰 | 勾上 = 只画、**不参与交互**（玩家走过它不会弹出交谈） |
| ☐ 会挡人 | 勾上 = 按站位分前后（人在它北边被它盖住） |
| ☐ 永远画在角色之上 | 给前景小物件用（一直盖着人，不按站位） |

**互动内容**面板会显示这件物件当前用**哪种写法**：

| 写法 | 面板上怎么编 |
| --- | --- |
| 单句旁白（`line`） | 一个输入框，写完事 |
| 多句对话（`talk`） | **一行一句**：说话人 / 左或右 / 立绘（下拉，含主角表情）/ 正文，行尾有 `↑` `↓` `✕`，底下「加一句」 |
| 挂剧情事件（`event`） | **只读**：显示它在 `data/events/<id>.json` 里，编辑器不编剧情正文 |
| 多动作菜单（`actions`） | 只读（暂不编辑） |

右边两个按钮可以在「单句旁白 / 多句对话」之间**换写法**（原内容会搬过去）。
挂了剧情事件或动作菜单的物件，编辑器不去动它 —— 想改成对话，得先去那个文件里把 `event` 摘掉。

> **说话人留空 = 旁白**；主角说话就填 `我`，侧别选**右**，立绘挑 `protagonist/…`
> （哪张表情用在哪，看美工那份《表情使用方法.txt》）。
>
> **编辑器不会把不认得的字段抹掉** —— 比如对话行里的 `size_delta`（字号增减）、
> `shake`（抖动）它不显示，但保存时原样留着。你要写这类效果，还是得手改 JSON。

### 7.5 删除与关联检查（防手滑）

删东西之前，编辑器会查**跨文件的关联**，有就列出来让你确认：

| 删什么 | 会提醒什么 |
| --- | --- |
| 物件 | 挂着剧情事件「ch1_sleep」／动作「睡下」挂着事件／有出现条件（if）／演完会写状态（item/key） |
| 传送点 | 连着地图「overworld」／挂着剧情事件／动作是 overworld／现在是锁着的 |

**为什么要拦**：这类错误**数据完全合法，`check_data` 查不出来** —— 它只查「引用的东西存不存在」，
查不出「这里本来该有个人来触发」。删掉之后正文文件还在，只是**再也没有入口**了。

同样地，给一件挂着剧情的物件勾上「**只装饰**」时也会先问一句（勾上它就不参与交互，
剧情同样触发不到）—— 这条是伪装成显示选项的陷阱，所以单独拦。

### 8. 前景层（那道「挡人的下围墙」，可以直接点它）

前景层是 `overlay`：一整张图，**恒在角色之上**，**整张拉伸到地图大小**。

**选中它**：切「选择」→ 点那块橙色虚线框里的地方。
它常常压在墙上、门洞上，别的层会先被点中 —— 想干净地点它，就把「墙 / 物件」
那两个勾**先取消**（显示开关同时管能不能点中）。选中之后面板上会出现：

| 控件 | 作用 |
| --- | --- |
| 图片 | 直接的路径输入框，敲完立刻换 |
| **导入图像…** | 挑一张 PNG 拷进 `art/map/`，按习惯命名 `<地图名>_wall`，并设为前景层 |
| 清除 | 把前景层去掉（数据里那条没了，图还留在 `art/map/` 里） |

**图的尺寸不用管** —— 游戏里它会被拉伸到整张地图（`map_view._add_overlay`）。
所以美术给的图多大都行。

**它没有位置和尺寸可调**：数据里前景层只有一条路径。那四个数字框对它自动禁用，
拖也拖不动。要改「挡住哪儿」，改的是**图本身**（画的时候就在图里定好了）。

**看它盖住了什么**：显示行最右那个「前景层」滑条拉淡。

**下围墙两种做法的分工**：

| 做法 | 数据长什么样 | 哪些图 | 编辑器的表现 |
| --- | --- | --- | --- |
| 前景层 | `overlay` 一个路径 | 卧室、委托屋、门卫室 | 铺一张图 + 橙色虚线框，**能选中、能换图** |
| 遮挡物件 | 一个 `cover: true` 的 actor | 集市（`bottom_wall`）、门卫室的桌子 | 绿框 + **可拖的黄基线** |

> 什么时候用哪种：人**只会**在它前面走 → 前景层（恒盖，最省事）；
> 人**既会在前面也会在后面**（门洞过道那种，人在前面时不能被墙压住）→
> 遮挡物件，按基线切换。

## 五、可走格（验「人到底能不能站这儿 / 走得过去」）

勾上「可走格」→ 面板底下会铺一层网格：

- **绿色格** = 人站得住（脚底方块 16×16 放得下）
- **红色格** = 站不住

**改完墙之后点一下「重算可走格」**（算一次要一两秒，它把整张图逐格问了一遍
`WalkGrid.is_free`）。

这一层是拿来验这几件事的：

- 新画的墙有没有把路堵死；
- 两道家具之间那条缝，够不够 16 像素的脚钻过去（缺口问题就是这么找出来的）；
- 门口那块传送区，里面到底有没有一格站得住。

---

### 更细的一把尺：**脚底框（跟鼠标）**

勾上显示行最后那个 **「脚底框（跟鼠标）」**，鼠标停在图上就会画出**主角的碰撞箱**：
那个 **16×16 的方块，以鼠标那个点为底、往上伸**（脚下一线为 0）。颜色就是答案：

- **绿** = 站得住，**红** = 站不住（判据直接调游戏那份 `WalkGrid.is_free`，不另算）
- 框旁边还写着落点坐标，量位置时能直接读数

**它和「可走格」的分工**：可走格是**整张图**的粗看（一眼看哪儿能走），
脚底框是**一个点**的精量 —— 「这条缝够不够人钻过去」「门口往里那一格站不站得住」
用它最准。改完墙它会立刻跟着变。
## 六、显示开关的两个作用（容易踩）

那一排勾选框**不只是显示/隐藏**，它同时决定「这一类能不能被点中」：

- 物件压在碰撞块上是常事（委托屋的书桌、门卫室的桌子）。物件开着的时候，
  你怎么点都是选中物件，底下那块墙**永远点不到** —— 这时把「物件」取消勾选，
  再点就选中墙了。
- 反过来也一样：只想调物件、不想误碰墙，就把「墙」关掉。
- 把某一类关掉时，**挂在它上面的选中会一起收起来**（不然会出现看不见的白框
  还挂着八个手柄）。

## 七、保存与回滚

- 改完点「保存到 JSON」→ 直接写回 `data/maps/<地图>.json`。
- **格式是对着 git 友好做的**：整数写成整数（`96` 不是 `96.0`），
  键序不动，两空格缩进 —— 只有你改过的那几个数字会出现在 diff 里。
- 覆盖已有地图前，编辑器会把磁盘上的旧 JSON 原样快照到
  `user://map_editor_backups/<地图 ID>/`，每张图最多保留最近 20 份；快照失败时保存会取消，不会覆盖原文件。
- 回滚旧版：点「备份历史…」选择时间点载入编辑器，检查后再点「保存到 JSON」；快照载入本身不会写磁盘。已提交版本仍可从 git 历史查看。
- 「重新载入（丢弃改动）」= 从磁盘重读，丢掉这次没保存的改动。

**保存完，游戏里不会自动变** —— 游戏每次进地图都从 JSON 读，
所以下次进那张图（或重新跑一次）就是新的。

---

### 没保存就切地图 —— 不会丢（草稿）

切到另一张图的**那一刻**，编辑器会先把这张图的改动**自动存成草稿**，切回来接着改。
草稿放在 `user://map_editor_drafts/`（**在仓库外面**，不会跟着 git 走，
`check_data` 也看不见它）。

怎么看哪张图有草稿：**地图下拉里带 ` *` 的就是**（`gatehouse *`）。
选中它载入时，状态栏会写「载入的是 xxx 的草稿（2026-09-27 12:30:05 存下的，还没保存）」。

想舍弃草稿：**「丢弃草稿」按钮**（会问一句）。别的途径也会清掉草稿：

| 动作 | 草稿 |
| --- | --- |
| 点「保存到 JSON」 | **清掉**（已写进仓库；覆盖旧地图前另留自动快照） |
| 点「重新载入（丢弃改动）」 | **连草稿一起丢**（这个按钮的意思就是「不要这些改动」） |
| 点「丢弃草稿」 | 清掉 |
| 直接切去别的图 | 留着，回来还在 |

> 草稿只记「这张图的 JSON 内容」。它不会替你保存美术、也不会碰到 `data/events/`。
