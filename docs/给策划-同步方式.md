# 给策划：怎么把改动发过来（避开 git 网络）

**背景**：这个仓库里有几百 MB 的美术，走网络 `git push`/`git pull` 传不完
（`git fetch` 还不支持断点续传，断了就从零开始）。所以以后同步走「打包给对方」这条路。

**你只需要做一件事：把你本地的内容打成一个包发过来。** 两种做法，挑一种。

---

## 做法一：不用终端（最省事）

1. 打开项目文件夹，找到里面的 **`.git`** 目录（隐藏文件夹，资源管理器要开「显示隐藏项目」）。
2. **整个 `.git` 目录复制出来**，压成 zip：`if-between-git.zip`（大概六七百 MB）。
3. 把 zip 发过来。

> 拷贝之前先确认 git 没在忙：GitHub Desktop 里没有转圈的同步、没有正在跑的合并。
> 拷到一半状态会坏掉。

⚠️ **前提：你改的东西必须先 commit。** 没提交的改动不在 `.git` 里，打包过去等于没发。
在 GitHub Desktop 里就是「写好提交信息 → Commit to main（或你的分支）」。

---

## 做法二：一条命令（包更小，推荐）

在项目文件夹里右键 → **Open Git Bash here**（或任何终端），敲：

```bash
git bundle create ../给项目组的包.bundle --all
```

会在**上一级目录**生成一个 `给项目组的包.bundle` 文件，把它发过来就行。

- 想更小：只装对方还没有的部分 ——
  `git bundle create ../增量.bundle <对方已有的提交>..HEAD`
  （对方会告诉你那个提交号）
- 这个文件是**一个文件**，比整个 `.git` 小，也不怕拷到一半。

同样**前提是先 commit**。

---

## 对方收到之后会做什么（你不用管）

收的人跑 `python tools/sync_from_package.py "<包路径>"`：会自动解开 zip、
拉进 `pkg/<分支>`、报「多了哪些提交、动了哪些数据文件」，然后跑完闸门再合并。
这个脚本就在仓库的 `tools/` 里，两边都有。

---

## 一句话版

**先 commit，再把 `.git` 压成 zip（或打成一个 `.bundle` 文件）发过来。**
