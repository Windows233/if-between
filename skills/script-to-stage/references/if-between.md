# 《IF：如果之间》接入说明

这是根据 2026-10-22 工作区观察整理的适配参考，不是剧情设定终稿。仅用于根目录具有 `project.godot`、`core/stage_step.gd`、`data/events/` 的本项目；使用时重新核实相关文件，不假设时间过去后仍相同。

## 读取顺序与可信度

- 剧情以用户本次指定原稿和明确采纳的修订为准。`学校/第二章.txt` 是到C组队处的早期正文，不含完整后半章。
- `docs/第二章9天团队执行策划案.md` 是内容与玩法方案，含未批准建议；`docs/追逐战与解救C玩法补充案.md` 声明替换旧案的两段追逐安排。它们不能无条件改写用户指定剧本。
- `docs/第二章9天制作计划.md` 是较早制作计划，不能作为最新剧情正文。
- 实现能力查 `core/stage_step.gd`、`core/story_node.gd`、`core/story_choice.gd`、`scenes/cutscene.gd` 的相关分派/函数，配合 `docs/工程约定.md` 与 `docs/IF机制.md`。文档注释可能过时，以当前执行逻辑核验。
- 资源绑定查对应 `data/maps/*.json`、`data/items.json`、`data/endings.json` 和实际路径。旧纪要中的“门卫室未接入”等进度说法可能已不符工作区。

本项目默认输出位置 `docs/staged_scripts/<事件>.stage.yaml` 和由它派生的 `.stage.md`。用户指定路径时遵从。生成文件不自动覆盖 `data/events/`。实际地图画面查验是前置要求，不是可选适配步骤，详见 `scene-grounding.md`。

## 已观察到的实际场景约束（每次重新核实）

- project.godot逻辑视口320×180。school_gate为421×281，school_yard为316×211。它们不是可自动缩全图的overworld；相机保持比例，按GameCamera.position_for夹边界。
- 操场PNG已经画着C（秋千左侧），ch2_swing却另在[220,85]生成临时C。救援编排必须先处理底图人物和独立角色重复，不能简单照抄旧事件当最终站位。
- 操场秋千actor为swing，rect=[190,38,58,42]、reach=[184,35,70,52]；墙体包括[190,61,58,17]和[228,69,21,11]。rect/reach中心不保证能站；脚底还向上延伸16像素。
- C目录现有down/up/side各4帧，Cutscene扫描这些方向并生成walk/idle；没有已核实的受困、挥刀、伸手动画，不把概念图里的姿势当帧动画。
- 校门can在南门右侧地面，rect=[215,234,12,14]、reach=[214,232,15,18]，无独立sprite，是底图物件加调查框。拾取钥匙并不自动让背景罐子消失。
- focus初次设置时camera_focus为null会立即切焦点，即使写time；不能假设从玩家跟随视角平滑推到目标。需要平滑镜头时说明现有约束或列小范围改动。
- hint调用Toast立即返回；右上角提示由LIFE=3.0和FADE=0.4自动管理。不要写成可直接配置两秒的现有指令。

## 从中间剧本到原生数据

以下是实现 AI 的转换注意事项。生成剧本阶段只记录 binding 与能力状态；用户要求接入后才改原生 JSON。

| 中间意图 | 当前对应 |
| --- | --- |
| 台词/旁白 | stage 中 `do: say`，lines 内 speaker/text/portrait/side；旁白可省 speaker，心声模式需要明确表达方式 |
| 屏幕中央文字 | `caption`，lines 必须是 `[{text: 一行}]`，不是字符串数组；默认会等确认，不重复加一次等待 |
| 淡黑/揭幕 | `fade` 的 to 为 black/clear |
| 日期地点/章标题/提示 | `location` / `banner` / `hint` |
| 大图出现/撤掉 | `image` / `image_hide` |
| 临时角色 | `npc` / `npc_move` / `npc_pose` / `npc_remove` |
| 玩家显隐/位置 | `hide_player` / `place_player` |
| 镜头 | `focus`；不带 at 恢复玩家；不要假设已有任意缩放、3D镜头或景深 |
| 切图/音频/等待/检查点 | `goto` / `music` / `play_sound` / `wait` / `wait_click` / `save` |
| 选择与条件出口 | 节点 choices 和 next_when，查当前条件解析器 |
| 状态 | 节点或选项的 set；这是赋值，不是天然增量；中间剧本的 add 必须核实如何实现 |
| 时机小游戏/追逐/潜行/任意并行组 | 不能假设已有对应 do；核实现状，尚未实现就写 planned/unresolved，不能编 `do: chase` 等指令 |

人物、道具和立绘 ID 都可能与显示名不同。中间剧本中的 speaker 是 entity ID，落地时转成用户可读称呼；portrait 资产 ID 需要转换为当前系统识别的相对路径。

## 必须保留的执行语义

1. 原生节点进入时先执行 `set`，然后 stage，再 talk，再 choices。中间文件中“展示物品时才获得”的 state cue，落地时需要拆节点，不能把 set 放在此前几句台词所在节点入口。
2. 节点 `ending` 表示终点，next 被忽略。只登记图鉴而继续剧情时，使用经核实的 `ending/<id>` flag；不要误用 ending 字段。
3. `image` 默认 `hide: true`。要留在画面上压台词，明确 `hide: false`，并在后续 `image_hide`。`wait_click` 等玩家，hold 是可提前点击结束的停留；不要把三秒 hold 当不可跳过锁定。
4. 大图位于对话框下面；caption 与章标题属于盖在对话框上的演出层。写清哪个图/字应在最前面，不随意给出未核实层号。
5. 临时NPC正常演出结束仍可能留在地图，切地图才清；需要退场时明确 npc_remove。带 talk 可在自由探索后交互。不要假设自由跟随、跨地图同行已经存在。
6. `place_player` 单独 at 是摆放；at 带 time 才表示走过去；path 是路线。当前移动为四方向路径，坐标/墙体/朝向要核验，不以文学“跑过去”猜一条穿墙直线。
7. `focus` 恢复镜头、遮罩揭开、底图含人时避免再叠同一角色、大图关闭都要显式编排。没有动作帧时，不把图中伸手/攻击姿势当作可用动画。
8. IF面板有自己固定的交换与判定规则，详见 `docs/IF机制.md`。不能把所有小游戏都改写成 IF，也不能擅自修改 if 位的语义。
9. `save` 是真实存档动作。结构稿可提出检查点，但不得默认引擎支持任意时刻精确恢复正在运行的小游戏、并行补间或输入状态。

## 目前应重新核实的剧情事项

它们用于提醒检查，不构成自动修订授权：篮球架拾取玩偶与净化后获得玩偶的版本差异；真正拒绝组队与后半章御守定位的依赖；回溯锚点和物品保留表；血迹来源；隐蔽与视觉发现的边界；End显示编号与稳定ID映射。

台词整理时不能把一份方案的建议悄悄拼进另一份原稿。冲突写入 decisions，说明来源和影响节点。只记录与当前剧本相关的冲突。

## 接入验收

用户只要演出剧本时，运行技能结构检查并人工审因果链即可。另要求接入后，按仓库当前约定运行 `tools/check_data.py`、相关剧情链检查和适用的 Godot 测试；再检查真实演出与导出包。静态数据自查不等于实际通关，不沿用旧文档里的测试数量冒充本次结果。
