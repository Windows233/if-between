# 每日策划与任务进度

产出能直接交给团队的任务方案。先核实进度，再安排下一步；不要把昨天的计划当成昨天已经完成，也不要把GitHub没有的成果当成没人做。

## 项目入口与数据

从当前项目向上定位`AGENTS.md`和`project.godot`，不要把安装目录当项目根。先读项目交接入口，按需定向查询，避免通读代码。

项目进度以`docs/项目进度.json`维护；历史用户确认、代码核查和未验收事项各有来源日期。每日计划存入`docs/每日策划/`。找不到这些文件时先查相同用途文件，不自动新建第二套进度账。核心方法及交付口径见[工作方法](references/workflow.md)；只在制定或调整排期时读取。

团队默认6人：用户负责策划协调，不给用户排产出；其余为程序、主美术、第二美术兼素材整合验收、文案、音效音乐。每人每天120分钟，包含沟通、等待依赖、导出和自检。制作D1至D6，D7至D9只修正与润色。最新用户调整覆盖这些默认约束；日期和D序号从进度账的起始日与实际工作安排核对，不仅凭当前日期假定任务做完。

## 核查实际状态

1. 查`git status`、近期历史、当前分支与`main/origin/main`。分别记录当前工作区、已提交分支、主线的状态；主工作区缺图但main已有，不能列为新缺口。联网失败应注明主线查询时点，不装作已更新远端。
2. 先纳入本轮用户明确报告，保留原意和日期。用户说“做好但没交GitHub”，登记制作完成、未交付或未合入、待验收；只安排提交、合并与核验，不重写。用户说“素材做好但忘打包”，安排补收或跳过，不安排重新画。
3. 对当天关键链查事件入口、地图交互、物品状态写入/读取、下一步出口及实际资源引用。文件存在仅代表素材有了；地图存在不代表可达；旧文档说完成不能覆盖当前证据。需要认图时查看原图，不只用文件名推断。
4. 核对最新批准的剧情正本、已作废设计和本轮修订。旧方案的结局编号、玩法或道具用途不能自动沿用。区分必要剧情信息和可替代的视觉表现；追逐或盒子规则未定时给可审阅方案，不当成已锁定需求。
5. 对无交付证据的昨日任务写“待确认”，给有稿/无稿两种执行入口；不要每天把同一未确认事项当新制作任务重新编号。完成的旧任务保留记录，不删除证据。

## 更新与安排

将制作、交付、合入、验收分别更新，附用户原话/提交/文件/运行结果。没有实测就不能把“待验收”改为“通过”；不要计算没有定义的整体完成百分比。

以最短可玩链排程序任务，优先补交、主线阻断和复用现有工具。让文案提供节点正文、分支结果、状态与声音表，让第二美术承担可独立完成的出图、清点或视觉验收。不要把所有录入和找素材都压给程序。

每项明确：负责人、前置条件、要做什么、分钟数、交付位置/格式、验收步骤、超时的最小交付。一天优先一条可运行链，复杂功能拆首版与联调；不以vibe coding或AI出图为由省略检查工时。

未交付前置不能当作已经可用。有独立工作就先排；依赖拿不到时给同工时替代任务，替代不叠加工时。必要图不到可用清楚标注的临时文字/现图联调，正式美术验收仍挂起。

完整需求账与当日产能分开。一次列全可以含可选项；不能为塞进两小时而删掉主线因果，也不能把剩余任务无差别拖进D7至D9。写清先砍的CG、额外动作或复杂关卡表现，保留剧情、关键道具、正确反馈与存读档。

## 输出与核验

- 先给当前完成/未交付/待确认/真正缺口的简明状态，再给5名成员当天任务与分钟数，最后给D6以前依赖路线、D7至D9润色重点和延期降级条件。
- 用户沿用Word团队稿时交付可直接转发的Word，并保留同内容Markdown和结构化任务数据。按可用documents技能渲染并逐页检查，不在团队稿里写会话经过。
- 输出结构化计划时，用`day_plan.json`的`date/day/tasks`字段；每条任务含`id/owner/minutes/work/deliverable/acceptance/depends_on/fallback`。将项目根的`tools/validate_daily_plan.py`用于核对日工时、必要字段和任务编号；这不替代业务审查。
- 检查已完成项是否仍被派为新制作、哪些依赖未交、5人各自总工时是否超过120分钟、未定玩法是否写成既成事实、是否未经授权改动游戏/发送消息。
- 编计划不等于执行游戏开发。只更新进度、计划和用户要求的技能；提交推送遵守仓库规则，不夹带别人的改动。用户明确指定程序会话时可交接，否则提供可转发的程序工作说明，不猜测收件人。
- 接收已有代码时区分“整理本地提交”和“推送交付”：先准备，再做功能验收与仓库闸门，全部通过后才推送。不能把程序任务排成先推GitHub、后检验；检查失败就保留待交付并记录阻断。

本技能在用户要求每日策划案或更新分工时触发，不创建定时任务、不自行每天唤醒。项目入口规则与安装副本负责发现，当前进度始终从项目账本读取，不把某天的状态固化进技能。
